Firewall Rules

Build a rule table from written requirements, put rules in the order that makes them work, and trace packets through a finished policy.

How a firewall reads its rules
  • It checks rules from the top down and acts on the first rule that matches. Rules below it are never checked.
  • A packet that matches nothing is denied by the hidden rule at the end.
  • So specific rules go above general ones, and a deny that overrides a permit must sit above it.

PBQ 1 · Firewall configuration

Build the DMZ rule table

Fill in the five rules so the firewall does exactly what is listed below. Rule 1 is checked first.

Requirements
  1. Anyone on the internet can reach the public website on the web server, over an encrypted connection only.
  2. Mail servers on the internet can deliver email to the mail server.
  3. LAN hosts can resolve names using the DMZ DNS server.
  4. Only the admin workstation can open encrypted remote command-line sessions to any DMZ server.
  5. All other traffic is blocked.

Each requirement becomes one rule, in the same order.

Explanation
  1. HTTPS to the web server: TCP 443 from Any to 10.0.5.10 only. "Encrypted only" rules out TCP 80, and the destination is the one server, not the whole DMZ.
  2. Inbound mail: server-to-server mail delivery is SMTP on TCP 25. Ports 587 and 465 are for mail clients submitting mail, not for delivery between servers.
  3. DNS lookups: UDP 53 from the LAN subnet to 10.0.5.53. Large responses and zone transfers fall back to TCP 53. This requirement only asks for name resolution, which is UDP.
  4. Admin access: encrypted remote command line is SSH on TCP 22. The source is the single host 10.0.1.50, not the LAN subnet, and the destination is the DMZ subnet because the requirement says any DMZ server. Telnet (23) is unencrypted and RDP (3389) is a graphical session.
  5. Explicit deny: most firewalls already end with an implicit deny. Writing it out makes the policy obvious to the next admin and lets you log what it drops.
PBQ 2 · Rule order

Quarantine an infected host

PC 10.0.1.66 is infected and is calling out to an attacker's server.

Requirements
  • 10.0.1.66 loses all access through the firewall.
  • Every other LAN PC keeps web browsing and DNS lookups.
  • Everything else stays blocked.
Your task

Drag the four rules into an order that meets every requirement.

Explanation
  • The host deny goes first. 10.0.1.66 is inside 10.0.1.0/24, so if either permit came first, its web and DNS traffic would match the permit and never reach the deny.
  • The two permits can go in either order because no packet matches both: one is TCP 80/443 to anywhere, the other is UDP 53 to one server.
  • Deny any goes last. Placed any higher, it would block everything below it.
