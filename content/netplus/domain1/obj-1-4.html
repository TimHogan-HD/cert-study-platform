Ports & Protocols

TCP 3-Way Handshake

TCP vs UDP

FeatureTCPUDP
ConnectionConnection-oriented (3-way handshake: SYN, SYN-ACK, ACK)Connectionless — fire and forget
ReliabilityGuaranteed delivery, retransmission of lost packetsNo guarantee; best-effort
OrderingSequenced — packets arrive in orderNo sequencing
SpeedSlower (overhead for acknowledgment)Faster (no overhead)
Use CasesHTTP, HTTPS, FTP, SSH, SMTP, emailDNS queries, DHCP, SNMP, VoIP, streaming, TFTP

Port & Protocol Reference — By Category

Select a row (click, Enter, or Space) to flip the summary and view a real-world example.

Web Traffic
PortProtocolSummary
80 HTTP TCP Cleartext web traffic. Replaced by HTTPS for secure sites.Example: A legacy internal dashboard still loads on HTTP:80 until a TLS certificate is deployed and the site is redirected to HTTPS.
443 HTTPS TCP Encrypted web traffic. Standard for all modern websites.Example: A customer signs in to an ecommerce site over HTTPS so credentials and session cookies are encrypted in transit.
File Transfer
PortProtocolSummary
20 FTP Data TCP Active mode data channel. Port 21 = control. ⚠ Two ports!Example: During active-mode FTP, a server sends file data from port 20 to a client after commands are negotiated on port 21.
21 FTP Control TCP Command/control channel. Passive mode negotiates ephemeral port over 21.Example: A user authenticates to an old FTP server on port 21, then the client opens a passive high port for file transfer.
69 TFTP UDP No authentication, no directory listing. Used for network device firmware updates and PXE boot.Example: A switch pulls a boot image from a trusted local TFTP server during zero-touch provisioning.
445 SMB TCP Windows file sharing and print sharing. Also used by ransomware (WannaCry/EternalBlue).Example: A finance team maps a Windows network share over SMB:445, so admins tightly control lateral SMB access between VLANs.
Email
PortProtocolSummary
25 SMTP TCP Server-to-server email relay. Not for authenticated client submission.Example: A company mail gateway relays outbound messages to partner mail servers over SMTP:25.
587 SMTP Submission TCP Authenticated client-to-server submission. Preferred over port 25 for sending.Example: Outlook submits a user's sent mail to the organization mailbox service on port 587 with authentication.
110 POP3 TCP Downloads email from server and deletes it. Single-device model.Example: A kiosk mailbox downloads messages via POP3 to one local machine and removes them from the server.
995 POP3S TCP POP3 over TLS — encrypted POP3.Example: A legacy scanner mailbox still uses POP3 semantics but is secured by connecting on POP3S:995.
143 IMAP TCP Keeps email on server and syncs across devices. Multi-device model. Contrast: POP3 deletes.Example: A user reads the same mailbox from laptop and phone because IMAP syncs state from the server.
993 IMAPS TCP IMAP over TLS — encrypted IMAP.Example: A mobile mail client connects to IMAPS:993 so message headers and content stay encrypted on public Wi-Fi.
119 NNTP TCP Legacy newsgroup protocol. Rarely seen today.Example: A specialist archive mirror still syncs historical technical newsgroups over NNTP:119.
Remote Access
PortProtocolSummary
22 SSH TCP Encrypted remote shell access. Replaces Telnet (port 23).Example: A Linux admin uses SSH keys on port 22 to manage routers and servers without exposing passwords in cleartext.
23 Telnet TCP Cleartext remote access — insecure, legacy. Replaced by SSH.Example: A lab-only serial terminal server still exposes Telnet, so access is isolated to a management VLAN.
3389 RDP TCP (+UDP) Windows remote desktop. High-value attack target — should be VPN-gated.Example: Help desk staff connect to user workstations over RDP only after joining a company VPN with MFA.
Infrastructure Services
PortProtocolSummary
53 DNS UDP + TCP UDP for queries (≤512 bytes). TCP for zone transfers and large responses. Both matter!Example: A branch resolver sends normal lookups via UDP but falls back to TCP for large DNSSEC responses.
67 DHCP Server UDP Server listens on 67. Client sends Discover from port 68.Example: A newly connected laptop broadcasts DHCP Discover and the local DHCP service answers from UDP 67.
68 DHCP Client UDP Client source port during DORA process.Example: Packet capture during troubleshooting shows DHCP Requests sourced from UDP 68 on the endpoint.
123 NTP UDP Time synchronization. Critical for Kerberos auth — max 5-minute clock skew.Example: Domain controllers and clients sync to NTP so Kerberos ticket validation does not fail on skew.
514 Syslog UDP System event logging to a central server. UDP = no delivery guarantee; logs can be lost.Example: Firewall appliances send syslog events to a SIEM collector on UDP 514 for centralized alerting.
Directory Services & Authentication
PortProtocolSummary
88 Kerberos TCP/UDP Authentication protocol in Active Directory. Requires NTP sync (5-minute skew max).Example: A domain-joined Windows user signs in and receives a Kerberos ticket to access shared resources without re-entering credentials.
389 LDAP TCP Directory queries in cleartext. Risky on untrusted networks. Replacement: use LDAPS on port 636.Example: A legacy app binds to LDAP:389 for user lookups; modern hardening migrates that bind to LDAPS:636 to encrypt credentials and queries.
636 LDAPS TCP LDAP over TLS for encrypted directory queries and credential exchange.Example: Security policy requires all directory binds over LDAPS so password checks and group lookups are encrypted end to end.
49 TACACS+ TCP AAA for network device administration with full packet encryption. In many modern environments, RADIUS-based NAC is more common.Example: A legacy router admin team authenticates CLI logins against a TACACS+ server, while new wireless access is handled through RADIUS policies.
1812 RADIUS Auth UDP AAA for Wi-Fi and VPN access. Encrypts the password field and works with accounting on port 1813.Example: 802.1X enterprise Wi-Fi sends user credentials to a RADIUS server for allow/deny decisions before network access is granted.
1813 RADIUS Accounting UDP Tracks session start, stop, duration, and usage for auditing and chargeback workflows.Example: A network operations team uses RADIUS accounting logs to confirm VPN session durations during an incident investigation.
Network Management & Monitoring
PortProtocolSummary
161 SNMP Poll UDP Manager queries agents for device stats (CPU, interfaces, errors).Example: A monitoring platform polls router interfaces on UDP 161 every minute for utilization graphs.
162 SNMP Trap UDP Agents send unsolicited alerts (traps) to the manager. Direction: agent → manager.Example: A switch sends an SNMP trap on link failure so the NOC is alerted immediately.
VoIP & Conferencing
PortProtocolSummary
5060 SIP TCP/UDP VoIP call setup and teardown. Media (voice) travels on separate RTP ports.Example: An IP phone registers to a PBX over SIP:5060, then voice streams over negotiated RTP ports.
5061 SIPS TCP SIP over TLS — encrypted VoIP signaling.Example: A contact center encrypts SIP signaling on port 5061 so caller metadata is protected in transit.
1720 H.323 TCP Legacy VoIP signaling. Uses 1720 for call setup; media uses dynamic ports.Example: A legacy video conferencing bridge still negotiates sessions on H.323:1720 during phased migration to SIP.
Routing Protocols
PortProtocolSummary
179 BGP TCP Internet routing between ASes. Uses TCP for reliability.Example: An ISP edge router exchanges route updates with an upstream provider over BGP:179.
520 RIP UDP Legacy distance-vector routing. Max 15 hops. Mostly replaced by OSPF.Example: A small legacy branch still advertises local subnets with RIP while core routers run OSPF.
Database
PortProtocolSummary
1433 MS SQL TCP Microsoft SQL Server. Commonly targeted — often blocked at perimeter firewall.Example: An internal app server reaches SQL Server on 1433 while firewall rules block internet-originated traffic.

⚠ Exam Traps
  • DNS uses both UDP and TCP — don't say "DNS is always UDP." Zone transfers use TCP.
  • RADIUS uses UDP. TACACS+ uses TCP. This is the #1 RADIUS/TACACS+ mistake.
  • SNMP trap direction: agent sends trap TO manager on port 162. Manager polls agent on 161.
  • FTP has TWO ports: 20 (data) and 21 (control). Many questions test whether you know both.
  • IMAP (143) keeps mail on server. POP3 (110) downloads and deletes — important for multi-device scenarios.
Quick Recall — 1.4
  • SSH=22 | Telnet=23 | SMTP=25 | DNS=53 | DHCP=67/68 | HTTP=80 | HTTPS=443
  • SNMP: 161 (poll) / 162 (trap) — both UDP
  • RADIUS: 1812/1813 UDP | TACACS+: 49 TCP (full encryption)
  • RDP=3389 TCP | LDAP=389 / LDAPS=636 TCP | NTP=123 UDP | Syslog=514 UDP
  • TCP = reliable, connection-oriented | UDP = fast, connectionless
