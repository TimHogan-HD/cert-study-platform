TCP vs UDP

FeatureTCPUDP
ConnectionConnection-oriented (3-way handshake: SYN, SYN-ACK, ACK)Connectionless — fire and forget

File Transfer
PortProtocolSummary
22 SFTP TCP SSH File Transfer Protocol — rides over SSH on port 22. Always encrypted. Contrast: FTP (20/21) is cleartext.Example: An admin uses an SFTP client to securely copy config backups from a Linux server on port 22.
20 FTP Data TCP Active mode data channel. Port 21 = control. ⚠ Two ports!Example: After FTP login on port 21, the file itself is sent on port 20 in active mode.

69 TFTP UDP No authentication, no directory listing. Used for network device firmware updates and PXE boot.Example: A new switch downloads its startup config from a local TFTP server.
445 SMB TCP Windows file sharing and print sharing. Also used by ransomware (WannaCry/EternalBlue).Example: An employee opens a shared folder on a Windows file server over SMB:445.
Email
PortProtocolSummary
25 SMTP TCP Server-to-server email relay. Not for authenticated client submission.Example: One mail server sends outbound email to another mail server on port 25.
587 SMTPS TCP Authenticated client-to-server submission via STARTTLS. Preferred over port 25 for client sending.Example: Your mail app sends your message to your company mail server on SMTPS port 587.
110 POP3 TCP Downloads email from server and deletes it. Single-device model.Example: A kiosk mailbox downloads messages to one PC and removes them from the server.
995 POP3S TCP POP3 over TLS — encrypted POP3.Example: A scanner mailbox checks mail on POP3S:995 so the connection is encrypted.
143 IMAP TCP Keeps email on server and syncs across devices. Multi-device model. Contrast: POP3 deletes.Example: A user reads the same mailbox on phone and laptop because IMAP keeps mail on the server.
993 IMAPS TCP IMAP over TLS — encrypted IMAP.Example: A phone app connects on IMAPS:993 to sync email securely on public Wi-Fi.
119 NNTP TCP Legacy newsgroup protocol. Rarely seen today.Example: A hobby archive server still mirrors old newsgroup posts on NNTP:119.
Remote Access
PortProtocolSummary
22 SSH TCP Encrypted remote shell access. Replaces Telnet (port 23).Example: An admin uses SSH:22 to run commands on a Linux server.
23 Telnet TCP Cleartext remote access — insecure, legacy. Replaced by SSH.Example: A lab switch still allows Telnet:23 for testing on an isolated network.
3389 RDP TCP (+UDP) Windows remote desktop. High-value attack target — should be VPN-gated.Example: Help desk connects to a user workstation over RDP after joining the company VPN.
Infrastructure Services
PortProtocolSummary
53 DNS UDP + TCP UDP for queries (≤512 bytes). TCP for zone transfers and large responses. Both matter!Example: A PC asks DNS for example.com over UDP 53, and large replies can switch to TCP 53.
67 DHCP Server UDP Server listens on 67. Client sends Discover from port 68.Example: When a laptop joins Wi-Fi, the DHCP server replies from UDP 67 with an IP address.
68 DHCP Client UDP Client source port during DORA process.Example: In a packet capture, the client sends DHCP requests from UDP 68.
123 NTP UDP Time synchronization. Critical for Kerberos auth — max 5-minute clock skew.Example: Workstations sync time with the NTP server so logins and timestamps stay correct.
514 Syslog UDP System event logging to a central server. UDP = no delivery guarantee; logs can be lost.Example: Routers send log messages to a central syslog server on UDP 514.
Directory Services & Authentication
PortProtocolSummary
88 Kerberos TCP/UDP Authentication protocol in Active Directory. Requires NTP sync (5-minute skew max).Example: A user signs in to Windows and gets a Kerberos ticket to open a file share.
389 LDAP TCP Directory queries in cleartext. Risky on untrusted networks. Replacement: use LDAPS on port 636.Example: An old app checks usernames over LDAP:389 without encryption.
636 LDAPS TCP LDAP over TLS for encrypted directory queries and credential exchange.Example: A modern app checks users over LDAPS:636 so directory traffic is encrypted.
49 TACACS+ TCP AAA for network device administration with full packet encryption. In many modern environments, RADIUS-based NAC is more common.Example: Network admins sign in to routers through a TACACS+ server.
1812 RADIUS Auth UDP AAA for Wi-Fi and VPN access. Encrypts the password field and works with accounting on port 1813.Example: Enterprise Wi-Fi sends login credentials to RADIUS on UDP 1812.
1813 RADIUS Accounting UDP Tracks session start, stop, duration, and usage for auditing and chargeback workflows.Example: RADIUS accounting on UDP 1813 logs when VPN sessions start and stop.
Network Management & Monitoring
PortProtocolSummary
161 SNMP Poll UDP Manager queries agents for device stats (CPU, interfaces, errors).Example: A monitoring tool polls a switch on UDP 161 for interface status.
162 SNMP Trap UDP Agents send unsolicited alerts (traps) to the manager. Direction: agent → manager.Example: A switch sends an SNMP trap when a link goes down.

IP Protocol Types

These are Layer 3 IP protocol numbers — the value in the IP header's Protocol field that identifies which upper-layer protocol the payload belongs to. Distinct from TCP/UDP port numbers.

Protocol #NameNotes
1ICMPDiagnostic and error reporting — ping, traceroute. No ports; operates directly at Layer 3. Not routable as a transport.
6TCPReliable, connection-oriented transport. 3-way handshake, sequencing, retransmission.
17UDPFast, connectionless transport. No handshake, no guaranteed delivery.
47GREEncapsulates other protocols inside IP tunnels. Used in site-to-site VPNs and PPTP. No built-in encryption.
50ESPIPSec component — encrypts and authenticates the packet payload. Most commonly used IPSec mode.
51AHIPSec component — authenticates the packet but does not encrypt. AH alone ≠ confidentiality.
UDP 500IKE / ISAKMPIPSec key exchange and SA negotiation. Uses UDP port 500; UDP 4500 for NAT traversal.

Traffic Flow Types

TypeDirectionDescriptionExamples
UnicastOne → OneSingle source to a single destination. The vast majority of internet traffic.HTTP/HTTPS browsing, SSH sessions, email delivery
MulticastOne → GroupSingle source to a subscribed group of receivers. Hosts join groups via IGMP. Efficient — one stream, many recipients.IPTV, OSPF/EIGRP routing updates (224.0.0.x), video conferencing
BroadcastOne → AllSingle source to all hosts in the broadcast domain. Contained by routers — does not cross Layer 3 boundaries.ARP requests, DHCP Discover
AnycastOne → NearestMultiple nodes share the same address; traffic routes to the topologically nearest one. Required in IPv6.DNS root servers, CDN edge nodes, IPv6 router discovery
Multicast vs Broadcast

Broadcast goes to every host in the subnet whether they want it or not. Multicast goes only to hosts that have explicitly joined the group via IGMP. IPv6 eliminates broadcast entirely — it uses multicast and anycast instead.

Exam Traps
  • DNS uses both UDP and TCP — don't say "DNS is always UDP." Zone transfers use TCP.
  • RADIUS uses UDP. TACACS+ uses TCP. This is the #1 RADIUS/TACACS+ mistake.
  • SNMP trap direction: agent sends trap TO manager on port 162. Manager polls agent on 161.
  • FTP has TWO ports: 20 (data) and 21 (control). Many questions test whether you know both.
  • IMAP (143) keeps mail on server. POP3 (110) downloads and deletes — important for multi-device scenarios.
  • SFTP uses port 22 — it is SSH-based file transfer, not FTP. FTP is 20/21 and cleartext; SFTP is always encrypted.
  • ESP (50) encrypts and authenticates. AH (51) authenticates only — AH provides no confidentiality.
  • Broadcast is confined to the subnet — routers do not forward it. Multicast requires IGMP group membership. Anycast routes to the nearest node, not all nodes.
Quick Recall — 1.4
  • SSH=22 | Telnet=23 | SMTP=25 | DNS=53 | DHCP=67/68 | HTTP=80 | HTTPS=443
  • SNMP: 161 (poll) / 162 (trap) — both UDP
  • RADIUS: 1812/1813 UDP | TACACS+: 49 TCP (full encryption)
  • RDP=3389 TCP | LDAP=389 / LDAPS=636 TCP | NTP=123 UDP | Syslog=514 UDP
  • TCP = reliable, connection-oriented | UDP = fast, connectionless
  • SFTP=22 TCP (SSH-based, always encrypted) | FTP=20/21 TCP (cleartext) | SMTPS=587 TCP (STARTTLS)
  • IP protocol numbers: ICMP=1 | TCP=6 | UDP=17 | GRE=47 | ESP=50 | AH=51 | IKE=UDP 500
  • Unicast=one→one | Multicast=one→group (IGMP) | Broadcast=one→all-in-subnet | Anycast=one→nearest
