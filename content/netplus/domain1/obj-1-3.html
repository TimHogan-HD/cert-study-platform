1.3 Cloud Concepts & Connectivity

Cloud computing delivers shared, on-demand infrastructure and services over a network. N10-009 tests service models, deployment types, virtualization concepts, and cloud-specific networking constructs.

KEY DISTINCTION
DHCP lease = address assigned automatically for a finite duration; the client can end up with a different address next time. Static (reservation) = a specific MAC always gets the same IP from the DHCP pool. Manual static = configured directly on the host, no DHCP involvement at all. Reservations are the right answer for printers and servers that need DNS-stable addresses.

Cloud Deployment Models

Public Cloud Shared
Shared infrastructure owned and operated by a Cloud Service Provider. Resources shared among many customers via multitenancy — you pay for what you use.
AWS, Microsoft Azure, Google Cloud Platform
Private Cloud Dedicated
Cloud infrastructure dedicated to one organization. On-premises or hosted privately — greater control, compliance, and security at higher cost.
VMware vSphere, OpenStack, AWS Outposts
Hybrid Cloud Mixed
Combination of public and private. Workloads move between environments based on policy — sensitive data on-premises, burst capacity in public cloud.
Azure Arc, AWS Direct Connect to on-prem datacenter
Multi-Cloud Multiple CSPs
Using multiple public CSPs simultaneously to avoid vendor lock-in, optimize costs, or leverage regional presence. Adds operational complexity.
AWS + Azure + GCP simultaneously
Community Cloud Shared Sector
Infrastructure shared by several organizations with common concerns — regulatory, compliance, or mission. More controlled than public, less costly than each running private.
Government clouds (FedRAMP/GovCloud), healthcare consortiums

Not in official objectives Objective 1.3 lists public, private, and hybrid as deployment models. Multi-cloud and community cloud are not enumerated. CompTIA states its lists are non-exhaustive, and both are kept because scenario questions use them as distractors for hybrid: multi-cloud combines several public providers, while hybrid combines public with private.

Network Virtualization

  • NFV (Network Functions Virtualization) — Replace physical appliances (routers, firewalls) with software running on commodity hardware.
  • Virtual NIC / VNIC — Software network interface for VMs; connects to virtual switch.
  • vSwitch (Virtual Switch) — Software switch within a hypervisor (VMware vSwitch, Hyper-V vSwitch). Connects VMs to each other and to physical NICs.
Exam Traps
  • IaaS = you manage OS and up. PaaS = you manage apps and data only. SaaS = nothing to manage. Misidentifying which layer the customer owns is a common distractor.
  • Shared responsibility ≠ shared equally — the provider always owns the physical data center and hypervisor layer; the customer always owns their data and access control.
  • Security Group / NSG = stateful (return traffic auto-allowed) vs NACL = stateless (must explicitly allow inbound AND outbound). Stateful/stateless is a frequent exam distinction.
  • Elasticity ≠ Scalability — elasticity is bidirectional (auto scale up AND down); scalability is capacity to grow. Cloud is elastic; traditional on-prem is merely scalable.
  • VPC peering is not transitive — if VPC A peers with B and B peers with C, A cannot reach C without a direct peer or Transit Gateway.
  • NFV replaces dedicated hardware with software on commodity x86 — it does not require specialized ASICs or proprietary hardware.
  • SDN separates control plane (decisions) from data plane (forwarding) via a centralized controller — see section 1.8 for full southbound/northbound API coverage.

Cloud Networking Deep Dive

NFV — Network Functions Virtualization

Replaces dedicated physical appliances (firewalls, load balancers, routers, WAN optimizers) with software running on commodity x86 servers or in cloud VMs. Enables faster deployment, elastic scaling, and lower CapEx. Cloud providers offer NFV-based services natively — e.g., virtual firewalls, virtual load balancers — as virtual appliances alongside IaaS instances.

VPC — Virtual Private Cloud

An isolated logical network within a public cloud provider's infrastructure. Defined by a CIDR block (e.g., 10.0.0.0/16). Subdivided into subnets (public and private). Connectivity options: VPC peering (direct VPC-to-VPC), Transit Gateway (hub-and-spoke between many VPCs), VPN Gateway, or Direct Connect/ExpressRoute. AWS-specific: new AWS accounts include a default VPC in each region; other providers use different defaults and terminology.

Scalability vs Elasticity

Scalability = the ability to add capacity (scale up/out) to handle more load. Elasticity = automatic bidirectional scaling — resources are provisioned when demand rises and de-provisioned when demand falls. Cloud infrastructure is elastic; traditional on-premises infrastructure is merely scalable (you provision for peak, waste capacity at off-peak).

Multitenancy

Multiple customers (tenants) share the same physical infrastructure while being logically isolated from one another. Logical isolation is enforced through hypervisors, VPCs, VLANs, and IAM policies. Multitenancy is the economic foundation of public cloud — shared infrastructure reduces per-tenant cost.

Quick Recall — 1.3
  • IaaS = VMs | PaaS = platforms | SaaS = apps (decreasing customer control)
  • NFV = physical appliances replaced by software on commodity x86 or cloud VMs
  • VPC = isolated logical cloud network; CIDR block, subnets, peering
  • Security Group/NSG = stateful, per-instance | NACL = stateless, per-subnet
  • Elasticity = auto bidirectional scaling (up AND down); Scalability = capacity to grow
  • Multitenancy = shared physical, logically isolated — foundation of public cloud economics
