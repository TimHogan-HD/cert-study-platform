Network Virtualization

  • NFV (Network Functions Virtualization) — Replace physical appliances (routers, firewalls) with software running on commodity hardware.
  • SDN (Software-Defined Networking) — Separates control plane (decisions) from data plane (forwarding). Centralized controller manages all devices.
  • Virtual NIC / VNIC — Software network interface for VMs; connects to virtual switch.
  • vSwitch (Virtual Switch) — Software switch within a hypervisor (VMware vSwitch, Hyper-V vSwitch). Connects VMs to each other and to physical NICs.

Cloud Networking Deep Dive

NFV (Network Functions Virtualization)

NFV replaces dedicated hardware appliances (routers, firewalls, load balancers) with software running on commodity x86 servers. The appliance function still exists but runs as a VM or container. Benefit: spin up/down on demand, no rack space, no hardware procurement lead time. All cloud provider "virtual appliances" (security groups, NAT gateways, virtual firewalls) are NFV implementations.

VPC (Virtual Private Cloud)

A VPC is an isolated, logically partitioned network inside a public cloud provider. You define the CIDR block, create subnets, attach gateways, and control routing within your VPC. Multiple VPCs do not see each other by default — VPC peering or a transit gateway connects them. Every AWS/Azure/GCP account gets a default VPC.

Scalability vs Elasticity

Scalability is the capacity to grow — adding servers, upgrading hardware. Elasticity is automatic bidirectional scaling in response to real-time load (scale out on demand, scale back in when load drops). Cloud is elastic; on-premises datacenters are typically only scalable. CompTIA treats these as distinct terms.

Multitenancy

Multitenancy means multiple customers share the same physical infrastructure with logical isolation. This is the economic foundation of public cloud. Your VM shares a physical host with other customers' VMs but cannot access their memory or storage.

⚠ Exam Traps
  • Spine-Leaf = data center design for east-west traffic. Three-tier = traditional enterprise (north-south traffic).
  • IaaS = you manage OS and up. PaaS = you manage apps and data only. SaaS = nothing to manage.
  • SDN separates control plane from data plane — know both terms.
  • Security groups (AWS) / NSGs (Azure) are stateful; Network ACLs are stateless. Not interchangeable — stateless ACLs require explicit rules for both directions.
  • Internet Gateway = bidirectional public access. NAT Gateway = outbound only (private hosts can initiate, cannot receive inbound).
  • Scalability = capacity to grow. Elasticity = auto-scaling in both directions. Cloud is elastic; on-prem is typically only scalable.
  • NFV = software appliances on commodity hardware. Not to be confused with SDN (control/data plane separation).
Quick Recall — 1.6
  • Three-tier: Core (speed) → Distribution (policy) → Access (endpoints)
  • Spine-leaf: data center, every leaf connects to every spine, equal latency
  • IaaS = VMs | PaaS = platforms | SaaS = apps (decreasing customer control)
  • SDN = control plane separated from data plane via centralized controller
  • NFV = software appliances on commodity x86 (no dedicated hardware)
  • VPC = isolated cloud network with your own CIDR, subnets, and routing
  • Security group/NSG = stateful per-instance | NACL = stateless per-subnet
  • Internet GW = bidirectional public | NAT GW = outbound only
  • Elasticity = auto-scale up and down | Scalability = capacity to grow | Multitenancy = shared hardware, logical isolation
