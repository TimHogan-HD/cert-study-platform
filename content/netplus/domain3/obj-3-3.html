3.3 Disaster Recovery Concepts

RPO vs RTO — Most Tested DR Terms

TermDefinitionSimple Question
RPO
(Recovery Point Objective)		 Maximum acceptable data loss, measured in time. How old can the restored data be? "How much data can we afford to lose?" → If RPO = 4 hours, backups must run every 4 hours.
RTO
(Recovery Time Objective)		 Maximum acceptable downtime. How quickly must systems be restored? "How long can we be down?" → If RTO = 1 hour, systems must be back up within 1 hour of failure.
MTTR
(Mean Time to Repair)		 Average time to restore a failed system/component. Lower MTTR = faster recovery capability.
MTBF
(Mean Time Between Failures)		 Average time between system failures. Higher MTBF = more reliable system. Used in hardware specs.

Backup Types

TypeWhat's Backed UpArchive Bit AfterRestore TimeStorage
Full All data, regardless of change Cleared Fastest (1 backup set) Most space
Incremental Only data changed since last backup (full or incremental) Cleared Slowest (need full + all incrementals) Least space
Differential All data changed since last full backup NOT cleared Medium (need full + latest differential) Grows over time until next full

Disaster Recovery Site Types

Site TypeDescriptionRTOCost
Hot Site Fully operational duplicate — live systems, real-time data replication. Just redirect traffic. Minutes to hours Very high
Warm Site Partially equipped — hardware present, data restored from backups. Some configuration needed. Hours to days Medium
Cold Site Just a space with power/connectivity — no hardware or data. Must provision everything. Days to weeks Lowest
Cloud DR Cloud-based failover — spin up cloud resources in another region on-demand. Minutes to hours (with automation) Pay-as-you-go

High Availability Concepts

  • Redundancy: Duplicate critical components — dual power supplies, redundant network links, multiple ISPs.
  • Failover: Automatic switch to backup system when primary fails (active-passive). Or both active simultaneously (active-active).
  • Load Balancing: Distributes traffic across multiple servers — improves performance AND provides failover if one server dies.
  • NIC Teaming / Bonding: Multiple NICs combined for bandwidth and redundancy. If one NIC fails, traffic continues on others.
  • UPS: Uninterruptible Power Supply — provides battery backup to bridge power outages and allow graceful shutdown.
  • Generator: Long-term power backup for extended outages (hours to days).
⚠ Exam Traps
  • RPO = data loss tolerance. "We can't lose more than 2 hours of data" → RPO = 2 hours. Backup frequency must match.
  • RTO = downtime tolerance. "Systems must be back up within 4 hours" → RTO = 4 hours.
  • Differential grows larger each day (until next full). Incremental stays small (only daily changes).
  • Restore from incremental = full + EVERY incremental. Differential = full + LATEST differential only.
  • Hot site costs the most. Cold site costs the least. RTO inversely correlates with cost.
Quick Recall — 3.3
  • RPO = how much data can be lost (backup frequency) | RTO = how fast to recover (downtime tolerance)
  • Full = all data | Incremental = changes since last backup (fast backup) | Differential = changes since last full
  • Hot site = live systems, minutes to recover | Warm = hours | Cold = days
  • MTBF = reliability (time between failures) | MTTR = recovery speed
