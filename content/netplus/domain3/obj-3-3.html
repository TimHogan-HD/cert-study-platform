DHCP, DNS & NTP

DHCP — DORA Process

DHCP automates IP address assignment. The DORA process is the four-step handshake:

D
Discover (Client → Broadcast)
Client has no IP. Sends broadcast (255.255.255.255) from 0.0.0.0. Asks "Is there a DHCP server?" Src port: 68, Dst port: 67.
O
Offer (Server → Broadcast/Unicast)
DHCP server responds with an IP address offer — IP, mask, gateway, DNS, lease time. Can be broadcast (client has no IP yet) or unicast.
R
Request (Client → Broadcast)
Client accepts the offer. Sends broadcast request so all servers know which offer was accepted (multiple servers may have offered).
A
Acknowledge (Server → Client)
Server confirms the lease. Client can now use the assigned IP address. Lease timer starts.

DHCP Relay (IP Helper)

DHCP uses broadcasts — routers don't forward broadcasts between subnets. A DHCP Relay Agent (configured with ip helper-address on the router) forwards DHCP broadcasts from clients to the DHCP server as unicast, enabling one DHCP server to serve multiple subnets.

DNS Hierarchy

  1. Root DNS Servers: 13 logical root server sets (a.root-servers.net through m.root-servers.net). Know where top-level domains (TLDs) are.
  2. TLD Name Servers: Manage .com, .org, .net, country codes (.uk, .de).
  3. Authoritative Name Servers: Hold actual DNS records for a domain. Final authority.
  4. Recursive Resolver: Your ISP or internal DNS server. Queries on behalf of clients, caches results (TTL-based).

NTP and Kerberos
Kerberos authentication (used in Active Directory) requires all devices to be within 5 minutes of each other in clock time. If NTP fails and clocks drift more than 5 minutes, Kerberos tickets will be rejected and users can't authenticate. NTP is security-critical.

How DNS Resolution Works

Query TypeWho InitiatesWho ReceivesResponse Type
RecursiveClient to resolverResolverFull answer (or NXDOMAIN) — resolver does all the work
IterativeResolver to each upstream serverRoot, TLD, authoritative nameserversReferral or answer — resolver asks each server separately
  1. Client sends recursive query to local resolver: "What is the IP for www.example.com?"
  2. Resolver checks cache. If found and TTL not expired, returns immediately (non-authoritative answer).
  3. Resolver sends iterative query to a root server → root responds with referral to .com TLD nameservers.
  4. Resolver sends iterative query to .com TLD → TLD responds with referral to example.com authoritative nameservers.
  5. Resolver sends iterative query to example.com authoritative → authoritative responds with A record answer.
  6. Resolver caches result per TTL, returns answer to client.
Authoritative vs Non-Authoritative Answers

An authoritative answer comes directly from the nameserver hosting the zone — it is definitive. A non-authoritative answer comes from a resolver's cache. The aa flag in dig output indicates an authoritative response. Use dig +trace to see the full iterative resolution chain.

Reverse DNS: PTR records use the in-addr.arpa hierarchy. A PTR query for 8.8.8.8 becomes a query for 8.8.8.8.in-addr.arpa. Used by mail servers for spam detection and by syslog to resolve source IPs to hostnames.

DNSSEC vs DoT vs DoH — Different Problems

DNSSEC protects data integrity — are the records authentic and unmodified? DoT and DoH protect query privacy — can someone see what you're looking up? They solve different problems and can be deployed together.

⚠ Exam Traps
  • DHCP uses broadcasts — routers don't forward broadcasts. You need a DHCP relay (ip helper-address) for multi-subnet DHCP.
  • PTR record = reverse DNS. A record = forward (name → IP). These are commonly confused.
  • CNAME cannot point to an IP address directly — it points to another hostname (which then resolves via an A record).
  • MX records have priority values — lower number = higher priority. Multiple MX records for redundancy.
  • DNS uses UDP for queries ≤512 bytes and TCP for zone transfers or larger responses.
  • NTP stratum 0 = hardware clock (not on network). Stratum 1 = first server on the network.
  • DNSSEC does NOT encrypt DNS responses — it signs them. A signed record proves authenticity but the content is still readable.
  • DoT = port 853. DoH = port 443 (same as HTTPS — intentionally uses this port to blend with web traffic and avoid blocking).
  • PTP is used where NTP is not precise enough (financial trading, 5G). NTS = NTP with security added — not a new time protocol.
