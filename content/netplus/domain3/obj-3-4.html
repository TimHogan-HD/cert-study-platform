3.4 IPv4 & IPv6 Network Services

DHCP — DORA Process

DHCP automates IP address assignment. The DORA process is the four-step handshake:

DORA Sequence — DHCP Handshake
D
Discover (Client → Broadcast)
Client has no IP. Sends broadcast (255.255.255.255) from 0.0.0.0. Asks "Is there a DHCP server?" Src port: 68, Dst port: 67.
O
Offer (Server → Broadcast/Unicast)
DHCP server responds with an IP address offer — IP, mask, gateway, DNS, lease time. Can be broadcast (client has no IP yet) or unicast.
R
Request (Client → Broadcast)
Client accepts the offer. Sends broadcast request so all servers know which offer was accepted (multiple servers may have offered).
A
Acknowledge (Server → Client)
Server confirms the lease. Client can now use the assigned IP address. Lease timer starts.
REMEMBER THIS
DORA — Discover, Offer, Request, Acknowledge — is the four-step DHCP exchange. Common DNS records: A = IPv4, AAAA = IPv6, CNAME = alias, MX = mail server, PTR = reverse lookup, TXT = SPF/DKIM/verification.

DHCP Relay (IP Helper)

DHCP uses broadcasts — routers don't forward broadcasts between subnets. A DHCP Relay Agent (configured with ip helper-address on the router) forwards DHCP broadcasts from clients to the DHCP server as unicast, enabling one DHCP server to serve multiple subnets.

DHCP Scope, Reservations & Exclusions

A scope is the pool of addresses a DHCP server offers for one subnet. Everything else here is a rule about which addresses inside that pool the server may hand out, and to whom.

SettingWhat it doesExample
ScopeDefines the address range, mask, gateway, and options served to one subnet. A server can host many scopes, one per subnet192.168.10.100 – 192.168.10.200 for VLAN 10
ExclusionAddresses inside the scope range that the server must never hand out — carved out for statically-addressed infrastructureExclude 192.168.10.100 – 192.168.10.110 for switches and printers configured by hand
ReservationBinds a specific MAC address to a specific IP inside the scope. The client still performs DORA and still holds a lease — it just always receives the same addressReserve 192.168.10.150 for the label printer's MAC
Lease TimeHow long a client may keep the address before renewing. Short leases suit guest and BYOD networks with high turnover; long leases reduce DHCP traffic on stable networks8 days on a corporate LAN, 2 hours on guest Wi-Fi
Reservation vs. Exclusion vs. Host-Side Static — A Classic Exam Item

All three end with a device holding a consistent IP address, which is exactly why they are confusable. The difference is who knows about the assignment:

  • Reservation — configured on the DHCP server. The device is still a DHCP client and still leases the address. Change the address centrally and the device picks it up on renewal. Best practice for printers and APs.
  • Exclusion — configured on the DHCP server, but assigns nothing. It only stops the server from leasing addresses you have assigned by hand elsewhere.
  • Host-side static — configured on the device. The DHCP server has no knowledge of it. If that address is not also excluded from the scope, the server can lease it to another host and cause an address conflict.

The exam-relevant pairing: a host-side static address needs a matching exclusion. A reservation needs neither, because the server is already the one making the assignment.

IPv6 Address Assignment — SLAAC vs. DHCPv6

IPv6 hosts can configure themselves without any server at all. SLAAC — stateless address autoconfiguration — is how that works, and it is the mechanism with no IPv4 equivalent.

1
Host joins the link and forms a link-local address (fe80::/10) so it can communicate before it has a routable address.
2
Router Solicitation: the host multicasts an ICMPv6 RS asking any router on the link to identify itself, rather than waiting for the next scheduled announcement.
3
Router Advertisement: the router replies with an RA carrying the /64 prefix for the link, the default gateway, and flags describing how the host should configure itself.
4
Host builds its own address: it appends a self-generated 64-bit interface identifier to the advertised prefix — historically EUI-64 derived from the MAC address, now usually a randomized value for privacy.
5
Duplicate Address Detection: the host checks that nobody else is already using the address before it starts using it.

The router hands out a prefix, not an address, and keeps no record of which host took what. That is what makes SLAAC stateless.

MethodWho assigns the addressServer keeps state?Typical use
SLAACThe host builds it from the RA prefixNo — no server involved at allDefault IPv6 behaviour; simple networks needing no per-host tracking
Stateless DHCPv6The host builds it via SLAAC; DHCPv6 supplies only the extra informationNo address state — it hands out DNS servers and domain search lists onlySLAAC networks that still need DNS configuration pushed centrally
Stateful DHCPv6The DHCPv6 server assigns the address, as DHCP does for IPv4Yes — it tracks which host holds which addressEnterprises needing address logging, auditing, or fixed assignments
The RA Flags That Decide

The Router Advertisement tells hosts which of the three modes to use. The M flag (Managed) set to 1 means "get your address from stateful DHCPv6." The O flag (Other) set to 1 means "build your own address, but ask DHCPv6 for DNS and other settings" — stateless DHCPv6. Both flags clear means pure SLAAC. DHCPv6 itself uses UDP 546 on the client and UDP 547 on the server — not 67/68, which are IPv4 DHCP.

DNS Hierarchy

  1. Root DNS Servers: 13 logical root server sets (a.root-servers.net through m.root-servers.net). Know where top-level domains (TLDs) are.
  2. TLD Name Servers: Manage .com, .org, .net, country codes (.uk, .de).
  3. Authoritative Name Servers: Hold actual DNS records for a domain. Final authority.
  4. Recursive Resolver: Your ISP or internal DNS server. Queries on behalf of clients, caches results (TTL-based).

DNS Zones

A zone is the portion of the DNS namespace a given server is responsible for. Zones come in two directions and two roles.

Forward vs. Reverse Zones

Zone TypeAnswersRecordsNaming
Forward Lookup Zone"What is the IP for this name?" — the direction almost all traffic usesA, AAAA, CNAME, MX, TXT, NS, SRVNamed for the domain itself: example.com
Reverse Lookup Zone"What name owns this IP?" — used by logging, mail filtering, and troubleshootingPTR recordsSpecial in-addr.arpa (IPv4) or ip6.arpa (IPv6) namespace, with the address written backwards — see the reverse DNS note below

Primary vs. Secondary Name Servers

RoleZone copyPurpose
Primary (master)Holds the read-write master copy — all edits are made hereThe single source of truth for the zone. Its SOA serial number increments on every change
Secondary (slave)Holds a read-only replica received from the primaryRedundancy and load distribution. Both are authoritative — a secondary's answer is just as authoritative as the primary's

A zone transfer is how the secondary gets its copy. The secondary polls the primary's SOA serial number; if it has increased, the secondary requests the zone. A full transfer is AXFR, an incremental one IXFR. Zone transfers use TCP port 53 — not UDP — because reliability matters more than speed for a bulk copy. Servers restrict which hosts may request a transfer, since an unrestricted one hands an attacker a complete map of the network.

Local Resolution — The Hosts File

Before a client sends a single DNS query, it resolves locally. The order is local cache → hosts file → DNS server, so a hosts file entry overrides DNS entirely — the query is never sent, and no amount of fixing the DNS server will change the answer.

PlatformLocation
WindowsC:\Windows\System32\drivers\etc\hosts
Linux / macOS/etc/hosts

This makes the hosts file useful for testing a cutover before changing public DNS — and a favourite persistence trick for malware, which adds entries redirecting security-vendor domains to 127.0.0.1. If one machine resolves a name differently from every other machine on the network, check its hosts file before suspecting DNS.

NTP and Kerberos
Kerberos authentication (used in Active Directory) requires all devices to be within 5 minutes of each other in clock time. If NTP fails and clocks drift more than 5 minutes, Kerberos tickets will be rejected and users can't authenticate. NTP is security-critical.
⚠ Exam Traps
  • DHCP uses broadcasts — routers don't forward broadcasts. You need a DHCP relay (ip helper-address) for multi-subnet DHCP.
  • PTR record = reverse DNS. A record = forward (name → IP). These are commonly confused.
  • CNAME cannot point to an IP address directly — it points to another hostname (which then resolves via an A record).
  • MX records have priority values — lower number = higher priority. Multiple MX records for redundancy.
  • DNS uses UDP for queries ≤512 bytes and TCP for zone transfers or larger responses.
  • NTP stratum 0 = hardware clock (not on network). Stratum 1 = first server on the network.
  • Reservation ≠ exclusion. A reservation assigns an address to a MAC from the server; an exclusion only withholds addresses so they can be assigned by hand. A host-side static address needs a matching exclusion or you risk an address conflict.
  • A hosts file entry overrides DNS. The client checks cache, then hosts file, then DNS — so one machine resolving a name "wrong" while others are fine is a hosts file problem, not a DNS server problem.
  • SLAAC is stateless — the router advertises a /64 prefix and the host builds its own address. Nothing tracks the assignment. Only stateful DHCPv6 keeps a record of who has which address.
  • DHCPv6 uses UDP 546/547, not the IPv4 DHCP ports 67/68.
  • A secondary name server is still authoritative. "Non-authoritative" means the answer came from a resolver's cache — not that it came from a secondary rather than the primary.

How DNS Resolution Works

Query TypeWho Does the WorkResponse
RecursiveResolver does all the work on behalf of the clientReturns the final answer (IP address) or an error — client gets a complete response
IterativeEach server gives the best answer it can (a referral or the answer)Resolver queries root → TLD → authoritative servers in sequence, following referrals
1
Client → Recursive Resolver: Client sends recursive query to its configured DNS resolver (e.g., ISP resolver or 8.8.8.8)
2
Resolver checks cache: If the answer is cached (TTL not expired), it returns immediately. Otherwise, resolution begins.
3
Resolver → Root Server (iterative): "Who handles .com?" Root server refers resolver to the .com TLD name servers.
4
Resolver → TLD Server (iterative): "Who handles example.com?" TLD server refers resolver to example.com's authoritative name servers.
5
Resolver → Authoritative Server (iterative): "What is the IP for www.example.com?" Authoritative server returns the A record.
6
Resolver → Client: Returns the answer and caches it for the record's TTL duration.
Authoritative vs Non-Authoritative Responses

An authoritative response comes directly from the zone's name server — it's the definitive source. A non-authoritative response comes from a resolver's cache. In dig output, the aa flag indicates an authoritative answer. Use dig +trace example.com to see the full iterative resolution chain.

Reverse DNS: PTR records map IP → hostname, stored in in-addr.arpa zones. Mail servers use reverse DNS to detect spam — a sending IP with no PTR record is suspicious.

DNS Security and Privacy Extensions

TechnologyPortProtocolPurposeWhat It Protects Against
DNSSEC53 UDP/TCPDigital signatures (RRSIG records)Integrity — signs DNS records so resolvers can verify they haven't been tampered withCache poisoning / DNS spoofing (does NOT encrypt queries)
DoT853 TCPDNS inside TLS tunnelPrivacy — encrypts DNS queries between client and resolverEavesdropping on DNS queries; easily distinguishable (port 853)
DoH443 TCPDNS inside HTTPSPrivacy — encrypts DNS queries; blends with HTTPS trafficEavesdropping; harder for enterprises to block/inspect than DoT
DNSSEC vs DoT vs DoH — The Key Distinction

DNSSEC = integrity. It signs DNS records with cryptographic signatures so you know the answer hasn't been forged. It does NOT encrypt queries — anyone can still see what you're resolving.
DoT / DoH = privacy. They encrypt the DNS query and response in transit. They do NOT validate the content of DNS records (that's DNSSEC's job).
These are complementary, not alternatives — DNSSEC + DoT together provides both integrity and privacy.

⚠ DNS Security Exam Traps
  • DNSSEC does NOT encrypt — it signs records for integrity verification. Queries are still visible in cleartext.
  • DoT = port 853; DoH = port 443. DoH uses the HTTPS port intentionally to blend with web traffic.
  • DoH is harder for enterprise security tools to block/inspect because it looks like HTTPS traffic.

⚠ Time Protocol Exam Traps
  • Use PTP when NTP is not precise enough — financial trading, 5G, and industrial control require sub-microsecond accuracy.
  • NTS = NTP + security — it's not a new time protocol; it adds authentication to NTP to prevent spoofing.
  • Know port numbers: NTP = 123 UDP | PTP = 319/320 UDP | NTS = 4460 TCP.
