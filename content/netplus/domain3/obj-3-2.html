3.2 Network Monitoring Technologies

Performance Metrics to Monitor

MetricDefinitionIssue When…
BandwidthMaximum data rate of a link (bps)Utilization consistently >80% — risk of congestion
ThroughputActual data transfer rate achievedFar below bandwidth — indicates loss, errors, or protocol overhead
LatencyTime for data to travel from source to destination (ms)>150ms one-way — VoIP quality degrades; >100ms round-trip may affect interactive apps
JitterVariation in packet delay (ms)>30ms — VoIP and streaming audio/video suffer
Packet LossPercentage of packets that don't arrive>1% — noticeable performance issues; >5% VoIP is unusable
Error RateRatio of errored frames to total framesAny significant errors — indicates physical layer issues

Anomaly Alerting & Notification

Collecting metrics is only half of it — a metric nobody looks at catches nothing. The baseline established in 3.1 is what makes alerting possible: it defines "normal" so the monitoring system can flag deviation from it and notify someone.

ConceptWhat it doesExam notes
Threshold AlertFires when a metric crosses a fixed value — WAN utilization above 80%, CPU above 90%Simple and predictable. Poorly chosen thresholds are the main source of alert fatigue
Anomaly AlertFires when current behaviour deviates from the baseline for that time and day, even if no fixed threshold is crossedCatches what thresholds miss — 40% utilization at 3 a.m. is normal at noon but anomalous overnight
NotificationDelivers the alert to a human or system — email, SMS, chat webhook, or a ticket raised automaticallyAlerts are usually tiered by severity so a Sunday-night page is reserved for genuine emergencies

SNMP (Simple Network Management Protocol)

ComponentRolePort
NMS (Manager)Polls agents for information; receives traps162 UDP (receives traps)
AgentRuns on managed devices (routers, switches); reports data; sends traps161 UDP (receives polls)
MIB (Management Information Base)Database of objects that can be monitored/managed. Each has an OID.—
OID (Object Identifier)Unique identifier for a specific data point (e.g., interface counters)—
Community StringPassword-like authentication in SNMPv1/v2c. "public" = read-only, "private" = read-write.—
SNMP VersionSecurityNotes
SNMPv1Community strings (cleartext)Original, no encryption or auth. Legacy.
SNMPv2cCommunity strings (cleartext)Adds bulk retrieval, improved error handling. Still cleartext.
SNMPv3Authentication + EncryptionThree security levels: noAuthNoPriv, authNoPriv, authPriv (SHA/AES). Enterprise recommended.
SNMP Trap vs Poll Direction
Poll (Get): NMS manager initiates — sends request to agent on port 161. Agent responds with data.
Trap: Agent initiates — sends unsolicited alert to NMS manager on port 162. Triggered by an event (interface down, high CPU, etc.)

Syslog

Syslog sends system log messages to a central syslog server (port 514 UDP). All devices can log to one central repository for correlation and compliance.

Syslog Severity Levels (0 = Most Severe)

LevelNameMeaningExample
0EmergencySystem is unusableComplete system crash, catastrophic failure
1AlertImmediate action requiredCore network device failure
2CriticalCritical conditionHardware failure, software exception
3ErrorError conditionsInterface errors, configuration errors
4WarningWarning conditionsDisk space low, high utilization
5NoticeNormal but significant eventsInterface up/down, user login
6InformationalInformational messagesNormal operational events
7DebugDebug-level messagesDetailed troubleshooting output — very verbose

Every Awesome Cisco Engineer Will Need Debugging Insight (Emergency, Alert, Critical, Error, Warning, Notice, Debug — levels 0–7, but Notice=5, Informational=6, Debug=7).

Monitoring Systems

SystemPurpose
NMS (Network Management System)Centralized platform for monitoring/managing network devices via SNMP, NetFlow, etc. (e.g., SolarWinds, PRTG, Zabbix).
SIEM (Security Information and Event Management)Collects and correlates log data from many sources for security analysis, alerting, and compliance reporting. (e.g., Splunk, QRadar, Microsoft Sentinel).
Packet Capture / Protocol AnalyzerCaptures raw network packets for deep inspection. Wireshark is the standard tool.

API Integration

SNMP polling is the traditional method; modern platforms increasingly pull device state through an API instead. Rather than walking a MIB for numeric OIDs, the monitoring system requests structured data — usually JSON or XML — directly from the device or from a cloud controller.

InterfaceWhat it isWhy it is used
REST APIHTTPS requests returning JSON; the standard interface for cloud-managed wireless, SD-WAN, and firewall platformsEasy to consume from scripts and dashboards; authenticated with a token rather than a community string
NETCONFXML-based protocol over SSH for retrieving and changing device configurationTransaction-based — a config change either fully applies or rolls back, unlike a partial CLI paste
RESTCONFREST-style HTTPS interface to the same YANG data models NETCONF usesCombines NETCONF's structured models with ordinary REST tooling
Why This Matters Beyond Monitoring

API access is what makes automation and IaC possible. The same interface that reports interface state can push configuration, so a monitoring system that detects drift from the golden config (3.1) can also remediate it. SNMP was designed primarily to read; APIs read and write.

⚠ Exam Traps
  • SNMP trap: agent sends TO manager on port 162. Manager polls agent on 161. Direction matters!
  • Syslog severity 0 = Emergency (most severe). 7 = Debug (least severe). Lower number = worse problem.
  • SNMPv3 is the only version with authentication AND encryption. SNMPv1/v2c = community strings (cleartext).
  • NMS ≠ SIEM. NMS focuses on device performance. SIEM focuses on security events and correlation.
  • Bandwidth ≠ throughput. Bandwidth is the link capacity; throughput is what you actually get.
  • Method ≠ solution — a method is how you collect (SNMP, flow, packet capture, API); a solution is what it answers (discovery, traffic, performance, availability, configuration). One method can feed several solutions.
  • Threshold ≠ anomaly — a threshold alert fires on a fixed number; an anomaly alert fires on deviation from the baseline. Anomaly detection catches problems that never cross a threshold.
  • Ad hoc discovery is run on demand by a person; scheduled discovery runs on a recurring interval. Only scheduled discovery keeps the asset inventory current.

Traffic Mirroring

Port Mirroring / SPAN

Copies traffic from one or more source ports (or VLANs) to a designated mirror port where a packet analyzer (Wireshark, IDS/IPS sensor) is connected. Traffic flows on the source port are unaffected — SPAN is non-intrusive. The mirror port is effectively read-only for analysis.

MethodScopeTransportUse Case
SPAN (local)Same switchSwitched portCapture traffic between ports on one switch; analyzer plugged in locally
RSPAN (Remote SPAN)Across switches via VLANDedicated RSPAN VLANAnalyzer on a different switch; mirror traffic sent across trunk using a reserved VLAN
ERSPAN (Encapsulated RSPAN)Across Layer 3 boundariesGRE tunnelAnalyzer in a different subnet or data center; mirror traffic encapsulated in GRE over IP
Network TAPInline on a cablePassive optical/electricalHardware tap inserted into fiber or copper — passively copies all traffic; no switch involvement; cannot be disabled by software

Monitoring Solutions

Objective 3.2 splits into methods and solutions. Everything above is a method — how data is gathered (SNMP, flow, syslog, packet capture, mirroring, APIs). A solution is what question the monitoring answers. The same method feeds several solutions: SNMP data can serve availability monitoring and performance monitoring at once.

SolutionQuestion it answersTypical tooling
Network Discovery"What is actually on the network?" — finds devices, addresses, and how they interconnect, building the topology and feeding the asset inventoryNmap, SNMP sweeps, LLDP/CDP neighbour data, NMS auto-discovery
Traffic Analysis"Who is talking to whom, and what is consuming the bandwidth?" — top talkers, application mix, unexpected flowsNetFlow/IPFIX/sFlow collectors, packet analyzers via SPAN or TAP
Performance Monitoring"Is it fast enough?" — latency, jitter, loss, throughput, and utilization measured against the baselineNMS polling, synthetic probes, IP SLA
Availability Monitoring"Is it up?" — reachability and uptime of devices, links, and services, and the source of most alertingICMP/port checks, SNMP traps, service health checks
Configuration Monitoring"Has anything changed that should not have?" — detects configuration drift from the approved baseline and flags unauthorized changesConfig backup and comparison tools, IaC platforms auditing against the golden configuration (see 3.1)

Network Discovery: Ad Hoc vs. Scheduled

ModeHow it runsWhen you use it
Ad HocRun on demand, by a person, against a chosen target rangeInvestigating a specific problem or verifying a change — "what is on this VLAN right now?" A point-in-time snapshot
ScheduledRuns automatically on a recurring interval — nightly or weekly sweepsKeeping the asset inventory and topology current, and catching rogue or unexpected devices that appear between sweeps
Quick Recall — 3.2
  • SNMP: Manager polls agent on 161 UDP | Agent sends trap to manager on 162 UDP
  • SNMPv3 = authentication + encryption (SHA/AES). v1/v2c = community strings only.
  • Syslog: 0=Emergency (worst) → 7=Debug (least severe). Port 514 UDP.
  • NetFlow = active flow export | sFlow = passive sampling | IPFIX = open standard of NetFlow
  • SIEM = security event correlation | NMS = network performance management
  • SPAN = same switch | RSPAN = across switches (VLAN) | ERSPAN = across L3 (GRE) | TAP = passive hardware
  • Jitter = packet delay variation — bad for VoIP | Latency = total one-way delay
  • Five solutions: network discovery | traffic analysis | performance | availability | configuration monitoring
  • Discovery: ad hoc = on-demand scan | scheduled = recurring inventory sweep
  • Configuration monitoring = drift detection against the golden config (3.1)
  • API integration: REST (JSON over HTTPS) | NETCONF (XML over SSH) | RESTCONF — read and write, unlike SNMP
  • Threshold alert = fixed value crossed | Anomaly alert = deviation from baseline
