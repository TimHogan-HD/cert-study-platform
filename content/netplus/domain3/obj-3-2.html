3.2 Network Monitoring Technologies

Performance Metrics to Monitor

MetricDefinitionIssue When…
BandwidthMaximum data rate of a link (bps)Utilization consistently >80% — risk of congestion
ThroughputActual data transfer rate achievedFar below bandwidth — indicates loss, errors, or protocol overhead
LatencyTime for data to travel from source to destination (ms)>150ms one-way — VoIP quality degrades; >100ms round-trip may affect interactive apps
JitterVariation in packet delay (ms)>30ms — VoIP and streaming audio/video suffer
Packet LossPercentage of packets that don't arrive>1% — noticeable performance issues; >5% VoIP is unusable
Error RateRatio of errored frames to total framesAny significant errors — indicates physical layer issues

SNMP (Simple Network Management Protocol)

ComponentRolePort
NMS (Manager)Polls agents for information; receives traps162 UDP (receives traps)
AgentRuns on managed devices (routers, switches); reports data; sends traps161 UDP (receives polls)
MIB (Management Information Base)Database of objects that can be monitored/managed. Each has an OID.—
OID (Object Identifier)Unique identifier for a specific data point (e.g., interface counters)—
Community StringPassword-like authentication in SNMPv1/v2c. "public" = read-only, "private" = read-write.—
SNMP VersionSecurityNotes
SNMPv1Community strings (cleartext)Original, no encryption or auth. Legacy.
SNMPv2cCommunity strings (cleartext)Adds bulk retrieval, improved error handling. Still cleartext.
SNMPv3Authentication + EncryptionThree security levels: noAuthNoPriv, authNoPriv, authPriv (SHA/AES). Enterprise recommended.
SNMP Trap vs Poll Direction
Poll (Get): NMS manager initiates — sends request to agent on port 161. Agent responds with data.
Trap: Agent initiates — sends unsolicited alert to NMS manager on port 162. Triggered by an event (interface down, high CPU, etc.)

Syslog

Syslog sends system log messages to a central syslog server (port 514 UDP). All devices can log to one central repository for correlation and compliance.

Syslog Severity Levels (0 = Most Severe)

LevelNameMeaningExample
0EmergencySystem is unusableComplete system crash, catastrophic failure
1AlertImmediate action requiredCore network device failure
2CriticalCritical conditionHardware failure, software exception
3ErrorError conditionsInterface errors, configuration errors
4WarningWarning conditionsDisk space low, high utilization

Every Awesome Cisco Engineer Will Need Debugging Insight (Emergency, Alert, Critical, Error, Warning, Notice, Debug — levels 0–7, but Notice=5, Informational=6, Debug=7).

ProtocolHow It WorksOrigin

Monitoring Systems

SystemPurpose
NMS (Network Management System)Centralized platform for monitoring/managing network devices via SNMP, NetFlow, etc. (e.g., SolarWinds, PRTG, Zabbix).
SIEM (Security Information and Event Management)Collects and correlates log data from many sources for security analysis, alerting, and compliance reporting. (e.g., Splunk, QRadar, Microsoft Sentinel).
Packet Capture / Protocol AnalyzerCaptures raw network packets for deep inspection. Wireshark is the standard tool.
⚠ Exam Traps
  • SNMP trap: agent sends TO manager on port 162. Manager polls agent on 161. Direction matters!
  • Syslog severity 0 = Emergency (most severe). 7 = Debug (least severe). Lower number = worse problem.
  • SNMPv3 is the only version with authentication AND encryption. SNMPv1/v2c = community strings (cleartext).
  • NMS ≠ SIEM. NMS focuses on device performance. SIEM focuses on security events and correlation.
  • Bandwidth ≠ throughput. Bandwidth is the link capacity; throughput is what you actually get.

Traffic Mirroring

Port Mirroring / SPAN

Copies traffic from one or more source ports (or VLANs) to a designated mirror port where a packet analyzer (Wireshark, IDS/IPS sensor) is connected. Traffic flows on the source port are unaffected — SPAN is non-intrusive. The mirror port is effectively read-only for analysis.

MethodScopeTransportUse Case
SPAN (local)Same switchSwitched portCapture traffic between ports on one switch; analyzer plugged in locally
RSPAN (Remote SPAN)Across switches via VLANDedicated RSPAN VLANAnalyzer on a different switch; mirror traffic sent across trunk using a reserved VLAN
ERSPAN (Encapsulated RSPAN)Across Layer 3 boundariesGRE tunnelAnalyzer in a different subnet or data center; mirror traffic encapsulated in GRE over IP
Network TAPInline on a cablePassive optical/electricalHardware tap inserted into fiber or copper — passively copies all traffic; no switch involvement; cannot be disabled by software
Quick Recall — 3.2
  • SNMP: Manager polls agent on 161 UDP | Agent sends trap to manager on 162 UDP
  • SNMPv3 = authentication + encryption (SHA/AES). v1/v2c = community strings only.
  • Syslog: 0=Emergency (worst) → 7=Debug (least severe). Port 514 UDP.
  • NetFlow = active flow export | sFlow = passive sampling | IPFIX = open standard of NetFlow
  • SIEM = security event correlation | NMS = network performance management
  • SPAN = same switch | RSPAN = across switches (VLAN) | ERSPAN = across L3 (GRE) | TAP = passive hardware
  • Jitter = packet delay variation — bad for VoIP | Latency = total one-way delay
