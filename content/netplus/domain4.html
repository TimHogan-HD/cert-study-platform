Objective 4.1

Network Security Concepts

CIA Triad

PrincipleDefinitionThreat ExampleControl Example
Confidentiality Only authorized parties can access data Eavesdropping, data theft, unencrypted transmission Encryption (TLS, AES), access controls, VPN
Integrity Data has not been altered or tampered with Man-in-the-middle modification, data corruption Hashing (SHA-256), digital signatures, checksums

MFA (Multi-Factor Authentication)
MFA requires two or more different factor types. A password + PIN is NOT MFA — both are "something you know." A password + authenticator app code = MFA (know + have).

TypeKeysSpeedUse CaseExamples

Hybrid Asymmetric to exchange key; symmetric for data Best of both TLS (HTTPS), SSH — real-world encryption TLS 1.3 (ECDH + AES)

PKI — Public Key Infrastructure

  • CA (Certificate Authority): Trusted entity that issues and signs digital certificates. (e.g., DigiCert, Let's Encrypt, internal enterprise CA).
  • Digital Certificate: Contains public key + identity information + CA signature. Proves "this public key belongs to this entity."
  • CRL (Certificate Revocation List): Published list of revoked certificates. Browser checks before trusting a cert.
  • OCSP (Online Certificate Status Protocol): Real-time cert validation — faster than downloading full CRL.
  • Root CA: The top of the trust hierarchy. Self-signed. Root CAs are embedded in OS/browser trust stores.
  • Intermediate CA: Signed by root CA; issues end-entity certificates. Allows root CA to stay offline.

Zero Trust Security Model

  • "Never trust, always verify" — no implicit trust based on network location.
  • Requires authentication and authorization for every access request, regardless of whether the user is on-premises or remote.
  • Least privilege: users and devices get minimum permissions needed.
  • Microsegmentation: divide network into small segments with strict access controls between them.

SAML vs SSO

SAML is the protocol; SSO is the outcome. SAML enables SSO across federated systems by allowing the IdP to assert identity to service providers without re-authentication. Geofencing is location-based access control — not a physical fence.

Security Terminology — Know the Distinctions

TermDefinitionExample
ThreatPotential cause of harm — the "what could go wrong"Ransomware, insider threat, natural disaster
VulnerabilityA weakness that can be exploitedUnpatched CVE, misconfigured firewall rule, default credentials
ExploitThe tool or technique used to take advantage of a vulnerabilityMetasploit module, phishing kit, SQL injection string
RiskProbability of a threat exploiting a vulnerability, resulting in impactRisk = Threat × Vulnerability × Impact
Threat vs Vulnerability vs Risk

A vulnerability does not become a risk until there is a threat capable of exploiting it. Patching removes the vulnerability; it does not eliminate the threat. A system with a known CVE but no network exposure has a vulnerability with low risk.

⚠ OT/ICS/SCADA — CIA Priority Order Is Inverted

In standard IT, the priority order is Confidentiality → Integrity → Availability. In OT/ICS/SCADA (industrial control systems), the priority is Availability → Integrity → Confidentiality. A power grid controller being inaccessible is catastrophic; a data breach, while serious, is secondary. This CIA inversion is a frequent exam scenario — know it cold.

⚠ Exam Traps
  • Confidentiality → encryption | Integrity → hashing | Availability → redundancy. Match the right control to the right principle.
  • MFA requires different factor TYPES. Two passwords ≠ MFA.
  • Asymmetric encryption is slow — not used for bulk data. TLS uses asymmetric for handshake then switches to symmetric.
  • MD5 is broken for security purposes. SHA-256 is the current standard.
  • SAML is the protocol; SSO is the outcome. SAML enables SSO across federated systems.
  • Geofencing = location-based access control (not a physical fence).
  • Vulnerability ≠ Risk. A vulnerability is a weakness; risk requires both a threat AND a vulnerability. Patching removes the vulnerability, not the threat.
  • PCI DSS requires CDE segmentation from all other networks. GDPR affects cloud region choice (data locality).
  • OT/ICS/SCADA: Availability is the top CIA priority — opposite of standard IT. Air gap or data diode for isolation.

  • Symmetric = same key, fast (AES) | Asymmetric = key pair, slow (RSA)
  • SHA-256 = current hash standard | MD5/SHA-1 = deprecated/broken
  • Zero trust = never trust, always verify; least privilege everywhere
  • SSO = one login, many systems | SAML = protocol enabling SSO | RBAC = role-based permissions

  • PCI DSS = CDE segmentation | GDPR = data locality | Data locality = geo constraints on cloud region
  • IoT/OT/ICS = isolated VLANs | SCADA = air gap or data diode | Guest = internet-only VLAN | BYOD = MDM or quarantine
  • OT/ICS CIA order: Availability → Integrity → Confidentiality (inverted vs standard IT)
Objective 4.2

Network Attack Types

Layer 2 Attacks

AttackMethodImpactMitigation
ARP Spoofing / Poisoning Attacker sends fake ARP replies, associating their MAC with a legitimate IP (e.g., default gateway). Poisons ARP cache of victims. On-path (MITM) attack — attacker intercepts all traffic meant for gateway. Can eavesdrop, modify, or drop packets. Dynamic ARP Inspection (DAI), static ARP entries, encrypted protocols (HTTPS, SSH)
MAC Flooding Attacker sends thousands of frames with random source MACs, overflowing the switch's MAC address table. Switch enters "fail-open" mode and floods all frames to all ports — effectively acts like a hub. Attacker can capture all traffic. Port Security (MAC address limits per port), DHCP snooping
VLAN Hopping (Switch Spoofing) Attacker's device acts as a switch and negotiates a trunk link (using DTP), gaining access to all VLANs. Attacker can send/receive traffic on any VLAN. Disable DTP on all access ports (switchport nonegotiate), disable unused ports, put access ports in manual mode
VLAN Hopping (Double Tagging) Attacker sends frame with two 802.1Q tags. Outer tag = native VLAN (stripped at first switch), inner tag = target VLAN (forwarded by second switch). One-way traffic to target VLAN — useful for DoS, difficult to intercept data back. Change native VLAN to unused VLAN (not VLAN 1), tag the native VLAN explicitly
STP Attack Attacker sends superior BPDUs to become root bridge — all traffic rerouted through attacker's device. On-path attack. Traffic disruption during STP convergence. BPDU Guard on access ports, Root Guard on non-core-facing ports

Network Layer Attacks

AttackMethodMitigation
DoS (Denial of Service) Single attacker sends massive traffic or exploits vulnerability to exhaust resources (bandwidth, CPU, connections). Rate limiting, firewall rules, upstream ISP filtering, traffic scrubbing
DDoS (Distributed DoS) Attack launched from thousands of compromised hosts (botnet) simultaneously. Much harder to block by source IP. Cloud DDoS mitigation (Cloudflare, Akamai), ISP black-holing, anycast routing
Reflection/Amplification Attacker sends small request with spoofed source IP (victim's IP) to servers (DNS, NTP, SSDP). Servers send large responses to victim. BCP38 (source IP validation), disable amplification services, rate limiting on DNS/NTP
DNS Poisoning / Spoofing Injects false DNS records into resolver cache. Clients resolve legitimate names to attacker's IP — fake website, credential theft. DNSSEC (signed DNS records), secure recursive resolvers, short TTL
On-Path (MITM) Attacker positions between two communicating parties (via ARP spoofing, rogue WAP, etc.) — reads and/or modifies traffic. Encryption (TLS/HTTPS), certificate validation, VPN, MFA, HTTPS Strict Transport Security (HSTS)
IP Spoofing Attacker sends packets with a forged source IP address. Used in amplification attacks and to evade detection. BCP38 egress filtering, uRPF (Unicast Reverse Path Forwarding)

Wireless Attacks

AttackMethodMitigation
Evil Twin (Rogue AP) Attacker creates a fake AP with the same SSID as legitimate network. Higher signal strength causes clients to connect to attacker's AP instead. WIDS (Wireless IDS), 802.1X authentication (not just PSK), user education
Deauthentication Attack Attacker sends spoofed deauth frames (management frames are unauthenticated in WPA2), disconnecting clients. Forces reconnect — can capture handshake for offline cracking. WPA3 (management frame protection - PMF/802.11w), WIDS
WPS Attack (Pixie Dust) WPS PIN brute force or Pixie Dust attack — exploits WPS protocol weakness to recover WPA2 passphrase in seconds. Disable WPS on all APs
Wardriving Driving around with a laptop/antenna to discover and map wireless networks. Used to find open or weak networks. Strong encryption (WPA3), minimal signal broadcast outside facility

AttackDescription

⚠ Exam Traps
  • DAI (Dynamic ARP Inspection) prevents ARP spoofing — requires DHCP snooping to be configured first.
  • Port Security limits MAC addresses per port — mitigates MAC flooding. Default action = shutdown port.
  • VLAN hopping via native VLAN (double-tagging) only works in ONE direction — attacker can send traffic to target VLAN but cannot receive responses directly.
  • Evil twin = fake AP with same SSID. Deauth attack = forces disconnect. These are different attacks but often combined.

  • DoS = single source | DDoS = botnet (distributed) | Amplification = spoofed source + large responses
  • On-path (MITM) = attacker between two parties | ARP spoofing is a common on-path technique
Objective 4.3

Network Hardening & Defense

Defense-in-Depth

Multiple overlapping security layers — if one fails, others prevent breach. No single control is sufficient.

  • Physical security → Network perimeter → Host-based → Application → Data → Monitoring

Firewall Types

TypeLayerCapability
Packet-FilteringL3/4Stateless. Checks src/dst IP, port, protocol. Simple ACL rules. Fast but limited.
Stateful InspectionL4Tracks connection state. Automatically allows return traffic. More secure than stateless.
NGFW (Next-Generation)L7DPI, application awareness, integrated IPS, SSL inspection, user identity, URL filtering. Gold standard.
WAF (Web Application Firewall)L7Protects web apps specifically. Blocks OWASP Top 10: SQLi, XSS, CSRF, etc.
Host-based FirewallL4/7Software firewall on individual host (Windows Firewall, iptables). First and last line of defense per host.
UTM (Unified Threat Management)L3–L7All-in-one appliance: firewall + IPS + antivirus + web filtering + email filtering + VPN in one device. Common in SMB environments. Performance tradeoff vs dedicated enterprise appliances.

IDS vs IPS Placement (Critical)

FeatureIDSIPS
PlacementOut-of-band / passive (SPAN/mirror port)Inline — traffic flows through it
Can Block?No — alert onlyYes — can drop/block malicious packets
Failure ModeFails safely — no impact on trafficIf fails, can cause outage (fail-open vs fail-closed)

DMZ Architecture

The DMZ (Demilitarized Zone) is a network segment between the internet and the internal network. Public-facing servers (web, email, DNS) sit in the DMZ — isolated from internal systems.

  • Traffic from internet can reach DMZ (with firewall rules).
  • Traffic from internet to internal network = blocked.
  • DMZ servers can connect to internal resources with strict rules (only specific ports/IPs).
  • Often implemented with two firewalls or a three-legged firewall (three interfaces).
Screened Subnet = DMZ

CompTIA N10-009 uses the term screened subnet as a synonym for DMZ. Both refer to the same architecture: a network segment isolated between two firewall boundaries where public-facing servers live. If an exam question says "screened subnet," it means DMZ.

Switch Security Features

FeaturePurposeWhat It Prevents
Port Security Limits number of MAC addresses allowed per port. Can sticky-learn or statically define allowed MACs. MAC flooding, unauthorized devices connecting to switch ports
DHCP Snooping Marks ports as trusted (uplinks) or untrusted (access). Only trusted ports can send DHCP offers/ACKs. Also builds binding table for DAI. Rogue DHCP servers, DHCP starvation attacks
DAI (Dynamic ARP Inspection) Validates ARP packets against DHCP snooping binding table. Drops ARP packets that don't match. ARP spoofing/poisoning (requires DHCP snooping first)
IP Source Guard Filters IP packets based on DHCP snooping binding table — only allows traffic from IPs/MACs that were legitimately assigned. IP spoofing at the access layer
802.1X NAC Requires authentication before granting network access at the port level. Port blocked until credentials verified by RADIUS. Unauthorized device access to the network

ACLs (Access Control Lists)

TypeMatch CriteriaNumber Range (Cisco)
Standard ACL Source IP address only 1–99, 1300–1999
Extended ACL Source + destination IP, protocol, port number 100–199, 2000–2699

ACL placement: Standard ACLs = place close to destination. Extended ACLs = place close to source (filter early, reduce unnecessary traffic).

Other Security Tools

ToolPurpose
HoneypotDecoy system designed to attract and detect attackers. Provides early warning and intelligence on attack techniques.
HoneynetNetwork of honeypots simulating a complete environment. More realistic and provides more intelligence than single honeypot.
Vulnerability ScannerAutomated tool that scans systems for known vulnerabilities without exploiting them. (e.g., Nessus, Qualys, OpenVAS).
Penetration TestingAuthorized simulated attack to identify vulnerabilities that can actually be exploited. More comprehensive than scanning.
⚠ Exam Traps
  • IDS = out-of-band (SPAN port), alerts only. IPS = inline, can block. This is the most important distinction.
  • DHCP snooping must be configured BEFORE DAI — DAI uses the DHCP snooping binding table.
  • Standard ACL = source IP only. Extended ACL = src + dst + port. Place standard ACLs near destination.
  • Honeypots are designed to attract attackers — they are NOT production systems. They intentionally have fake vulnerabilities.
  • Vulnerability scanning ≠ penetration testing. Scanning finds potential vulnerabilities. Pen testing exploits them.
  • Screened subnet = DMZ (same concept, different term). CompTIA N10-009 may use either term.
  • UTM = all-in-one security for SMB. NGFW = enterprise-grade DPI and application awareness. Both operate at L7 but NGFW is positioned as more performant for enterprise.
Quick Recall — 4.3
  • IDS = passive, SPAN port, alert only | IPS = inline, blocks traffic
  • NGFW = DPI + IPS + app awareness + SSL inspection
  • UTM = all-in-one (firewall + IPS + AV + web filter + email filter + VPN), common in SMB
  • Port security = MAC limits | DHCP snooping = rogue DHCP prevention | DAI = ARP protection (needs snooping)
  • Standard ACL = source IP only | Extended ACL = src+dst+port
  • DMZ = screened subnet = public-facing servers isolated between internet and internal network
