Duplex Mismatch — The Exam Favorite

Duplex Mismatch Pattern

Situation: One side of link is full-duplex, other side is half-duplex (or auto-negotiate mismatch).

Symptoms: Late collisions, runts, CRC errors on the half-duplex side; intermittent slowness; performance degrades under load.

Fix: Hard-code both ends to matching duplex and speed, or let both auto-negotiate (both sides must be set to auto).

Key rule: If one side is hardcoded and the other is auto, the auto side will negotiate speed correctly but default to half-duplex — causing a mismatch even though the link is up.

Incorrect Cable Selection

A cable can be terminated perfectly and still be the wrong cable. These faults present as "it works, but not at the speed or distance it should" — the link trains at a lower rate, or fails only on the longest runs. Port Status

A port that is not passing traffic is not necessarily faulty. Three states look similar from the user's side and have completely different causes — one is a protection mechanism firing, one is deliberate, one is a configuration mismatch. Distinguishing them is the exam-tested point.

StateCauseRecovery
Error disabled
(err-disabled)		 A protection mechanism shut the port down: BPDU Guard receiving a BPDU on an access port, a port-security violation, or repeated link flapping. Not automatic. shutdown then no shutdown on the interface, or configure errdisable recovery timers to re-enable it after an interval. Fix the underlying cause first or it will trip again.
Administratively down Someone shut the port deliberately with shutdown. This is a configuration state, not a fault — the port is doing exactly what it was told. no shutdown. Check change records before re-enabling: a port shut on purpose usually had a reason.
Suspended Most often an EtherChannel member port whose configuration does not match the rest of the bundle — mismatched speed, duplex, VLAN, or channel mode. Also seen on a VLAN suspended in the VLAN database. Align the member port's configuration with the bundle. The port is healthy; it is being excluded for inconsistency.
Reading the Difference

show interface distinguishes all three in its first line. "administratively down, line protocol is down" means someone shut it. "err-disabled" appears as the interface status in show interface status. A plain "down, line protocol is down" with no qualifier is the actual physical fault — cable, transceiver, or far-end device.

The security mechanisms that trigger err-disabled — BPDU Guard, Root Guard, port security — are covered in 2.2. Note the distinction made there: BPDU Guard puts the port in err-disabled and requires manual recovery, while Root Guard uses root-inconsistent state and recovers on its own.

Transceivers

FaultSymptomDiagnosis
Transceiver mismatchNo link, or a link that comes up and immediately dropsThe two ends do not match: single-mode transceiver against multimode fiber, different wavelengths (850nm vs 1310nm), or different speeds (SFP vs SFP+). Causes: dirty or scratched connector, tight bend, splice loss, or a run beyond the optic's rated distance. Clean the endfaces first — contamination is the most common cause.

dBm — Reading Optical Power

Optical power is negative in dBm: closer to zero is stronger. −3 dBm is a strong signal, −20 dBm is weak, and a typical multimode receiver bottoms out around −17 dBm. Each 3 dB of loss halves the power. If the measured level sits below the transceiver's rated receive sensitivity, the link will error or fail — that is the number to compare against, not an absolute threshold.

🎯 PBQ Prep — Cable Identification

What it looks like: Given a scenario description (e.g., "connecting two switches 80m apart requiring 10 Gbps") select the correct cable type and connector.

Key mappings to know cold:

  • 10G at 100m → Cat6A or fiber (Cat6 only supports 10G to 55m)
  • Long distance (>100m) → fiber (SMF for km-scale, MMF up to 550m)
  • Air-handling space → plenum-rated cable
  • Outdoor buried → direct-burial rated cable
  • Between buildings (electrical isolation) → fiber (no ground loop risk)
⚠ Exam Traps
  • OTDR is for fiber only — use TDR for copper
  • Late collisions are not the same as normal collisions — late = duplex mismatch
  • Toner probe finds a cable; loopback plug tests a port — different tools, different purposes
  • Light meter measures power (dBm); OTDR measures loss profile along the length — both are fiber tools
  • Err-disabled and administratively down are not the same thing — err-disabled is a protection mechanism firing, administratively down is someone typing shutdown. Neither is a cable fault.
  • Err-disabled does not clear itself — it needs shutdown/no shutdown or a recovery timer. Root Guard's root-inconsistent state does clear itself.
  • A transceiver mismatch and a dirty connector both show as errors — mismatch usually means no link at all, contamination means a link that is up but erroring
  • A PoE device that will not power on may be hitting the switch's total budget, not a dead port — check show power inline before swapping hardware
  • Optical power is negative dBm: closer to zero is stronger. Too much power on a short link is a real fault, not just too little.
  • Cat 8 is not "better Cat 6A for long runs" — it is 40 Gbps to 30m only, for data-centre use
  • STP only helps if its shield is properly bonded to ground; an ungrounded shield can make interference worse
✓ Quick Recall
  • Late collisions + runts + CRC = duplex mismatch
  • TDR = copper, OTDR = fiber, spectrum analyzer = wireless RF
  • Loopback plug tests a port (NIC/switch); toner probe traces/identifies a cable
  • Plenum cable required in air-handling spaces (FEP/Teflon jacket)
  • Cat6 = 10G at 55m; Cat6A = 10G at 100m
  • Fiber between buildings = electrical isolation (no ground loop)
  • Three port states: err-disabled (protection fired) · administratively down (deliberate shutdown) · suspended (EtherChannel config mismatch)
  • Err-disabled recovery = shutdown / no shutdown, or errdisable recovery timer
  • PoE device won't power on → show power inline → budget exhausted or wrong standard (802.3bt device on an 802.3af port)
  • Transceiver mismatch = no link. Low signal (dBm) = link up but erroring. Clean the connector first.
  • TX/RX transposed = no link at all; improper termination = link up with accumulating errors
  • Cat 6 = 10G/55m · Cat 6A = 10G/100m · Cat 8 = 40G/30m only
