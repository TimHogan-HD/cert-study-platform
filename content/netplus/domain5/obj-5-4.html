⚠ Objective 5.4 Coverage — Both Wired AND Wireless

CompTIA N10-009 objective 5.4 covers performance troubleshooting for both wired and wireless networks. Bandwidth saturation, bottlenecks, high latency, packet loss, and jitter are all 5.4 topics — as is the wireless content below. Expect exam questions on both.

Bandwidth vs. Throughput

Bandwidth is a link's capacity: the rate it is rated for, such as 1 Gbps. Throughput is the rate actually achieved end to end, which is always lower because of protocol overhead, retransmissions, and the slowest link on the path. When users say "the network is slow", measure throughput with iperf3 or a speed tester and compare it with the bandwidth of every link on the path. The link where the two are closest is the bottleneck.

How the Five Wired Symptoms Connect

Congestion (also called contention, when many hosts compete for one link) is the root of most wired performance problems. Once an interface's output queue fills, packets wait in the queue, which shows up as latency. The queue length keeps changing, so the waits vary, which shows up as jitter. When the queue overflows, the interface drops packets, which shows up as packet loss. One saturated link can therefore produce all five symptoms at once.

Worked Scenario — "Calls Break Up Every Afternoon"

A branch office reports choppy VoIP calls between 1 p.m. and 4 p.m. Pinging the head-office call server from a branch PC shows the symptoms; the branch router's WAN interface shows the cause; iperf3 confirms how little throughput is left.

Not in official objectives Objective 5.4 lists interference (including channel overlap), signal degradation or loss, insufficient wireless coverage, client disassociation issues, and roaming misconfiguration. The hidden node, sticky client, wrong PSK, RADIUS failure, evil twin, captive portal, and antenna placement rows are not enumerated. CompTIA states its lists are non-exhaustive, and they are kept because a user reports each of them as "the Wi-Fi is broken", just like the listed issues.

⚠ Exam Traps
  • 2.4GHz has only 3 non-overlapping channels: 1, 6, 11 — using any other combination causes overlap
  • Spectrum analyzer ≠ wireless analyzer — spectrum analyzer sees all RF (non-Wi-Fi too); wireless analyzer sees 802.11 only
  • Hidden node solution is RTS/CTS — not changing channels
  • Sticky client is a client-side decision — the AP can't force roaming without sending a deauth or using BSS transition management (802.11v)
  • RSSI is negative dBm — closer to zero = stronger signal (−40 is better than −80)
✓ Quick Recall
  • Obj 5.4 = BOTH wired performance AND wireless troubleshooting
  • Congestion = high latency under load; check show interface output drops + iperf3
  • Packet loss = CRC errors, duplex mismatch, or queue drops; jitter = inconsistent delay (QoS fixes it)
  • 2.4GHz non-overlapping channels: 1, 6, 11 only
  • RSSI closer to 0 = stronger (−40 > −80)
  • SNR >20 dB = good; <10 dB = poor
  • Hidden node fix: RTS/CTS
  • Sticky client: device stays on far AP; fix with band steering or deauth
  • Evil twin prevention: 802.1X certificate-based authentication
  • Spectrum analyzer identifies non-Wi-Fi interference; wireless analyzer shows 802.11 networks only
  • Roaming failure → enable 802.11r; configure RSSI roam threshold; band steering
