Common Wireless Issues

IssueSymptomCauseFix
Channel overlap / interference Slow speeds, high retransmits, inconsistent throughput Adjacent APs using overlapping channels (e.g., channels 2, 3, 4 in 2.4GHz) Use only channels 1, 6, 11 in 2.4GHz; use non-overlapping 5GHz channels
RF interference Intermittent drops, poor performance in specific areas Microwaves (2.4GHz), Bluetooth, baby monitors, neighboring Wi-Fi, cordless phones Spectrum analyzer to identify source; move to 5GHz; change channels
Hidden node problem Excessive collisions; two clients can't "hear" each other but both reach the AP Physical obstacles block direct client-to-client signal Enable RTS/CTS (Request to Send / Clear to Send) — forces coordination through AP
Sticky client Device stays connected to distant/weak AP even when closer AP is available Client controls roaming decision; older clients hold connections too long Band steering, 802.11r fast roaming, RSSI thresholds on controller, deauth to force reconnect
AP coverage gap Dead zones; signal drops to zero in specific areas Insufficient AP density, walls/obstacles attenuating signal Wireless site survey; add APs; adjust transmit power
Wrong PSK / passphrase Authentication failure; "incorrect password" error Client configured with wrong pre-shared key Re-enter passphrase; verify PSK on AP side
RADIUS auth failure Authentication fails in 802.1X environment Expired certificate, wrong RADIUS secret, NPS misconfiguration Check RADIUS logs; verify certificate validity; confirm shared secret matches AP config
Evil twin / rogue AP Users associate to attacker's AP; credentials stolen Attacker broadcasts same SSID with stronger signal 802.1X (certificate-based auth); rogue AP detection on wireless controller
Captive portal issues Browser doesn't redirect to login page; HTTPS sites block redirect HTTPS enforcement prevents captive portal redirect; DNS-based redirect blocked Modern devices use captive portal detection (HTTP probe to known URL); configure correctly
Antenna placement Dead zones in specific areas despite nearby APs; signal drops around corners or behind walls AP antenna aimed incorrectly; omnidirectional AP in long narrow hallway loses signal at ends Reposition AP; use directional antenna for long corridors; conduct active site survey; review heat map
Disassociation Client suddenly disconnects and sees "connection lost"; must reconnect AP-initiated deauthentication (load balancing, idle timeout, firmware bug, interference) Check wireless controller logs for deauth reason code; check interference sources; update AP firmware
Roaming failure Client drops connection when walking between AP coverage zones; sticky client stays on far AP Client controls roaming decision and won't release old AP; 802.11r fast BSS transition not configured Enable 802.11r fast roaming; configure RSSI threshold for AP to send deauth; enable band steering
Coverage gap / dead zone No signal in part of building; client loses association completely in specific areas Insufficient AP density; thick concrete/metal walls attenuating signal; AP placed too far Add AP; conduct wireless site survey; adjust transmit power; review heat map output

⚠ Exam Traps
  • 2.4GHz has only 3 non-overlapping channels: 1, 6, 11 — using any other combination causes overlap
  • Spectrum analyzer ≠ wireless analyzer — spectrum analyzer sees all RF (non-Wi-Fi too); wireless analyzer sees 802.11 only
  • Hidden node solution is RTS/CTS — not changing channels
  • Sticky client is a client-side decision — the AP can't force roaming without sending a deauth or using BSS transition management (802.11v)
  • RSSI is negative dBm — closer to zero = stronger signal (−40 is better than −80)
  • Objective 5.4 covers BOTH wired and wireless performance. Bottleneck, jitter, and packet loss are wired topics in this objective.
  • Output drops on show interface = queue overflow = link congestion — not a physical layer error.
  • Antenna placement affects dead zones — an omnidirectional AP placed at one end of a long hallway creates dead zones at the far end. Directional antennas solve corridor coverage.
✓ Quick Recall
  • 2.4GHz non-overlapping channels: 1, 6, 11 only
  • RSSI closer to 0 = stronger (−40 > −80)
  • SNR >20 dB = good; <10 dB = poor
  • Hidden node fix: RTS/CTS
  • Sticky client: device stays on far AP; fix with band steering or deauth
  • Evil twin prevention: 802.1X certificate-based authentication
  • Spectrum analyzer identifies non-Wi-Fi interference; wireless analyzer shows 802.11 networks only
  • Bottleneck = single slow hop | Congestion = link saturation | Jitter = delay variation (VoIP killer)
  • Output drops in show interface = queue overflow = congestion | iperf3 = active throughput test
  • Roaming failure: enable 802.11r | Disassociation: check controller deauth reason code | Dead zone: site survey + add AP
