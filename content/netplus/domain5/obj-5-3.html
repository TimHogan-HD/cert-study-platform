APIPA — Diagnostic Indicator

169.254.x.x — What It Means

If a Windows device self-assigns an address in 169.254.0.0/16 (APIPA — Automatic Private IP Addressing), it means DHCP failed. The device sent DHCP Discover broadcasts but received no Offer within timeout.

Diagnose: Is the DHCP server down? Is there a DHCP relay (ip helper-address) misconfigured? Is the client on the wrong VLAN where no DHCP server exists?

APIPA devices can communicate only with other APIPA devices on the same link — no internet, no cross-subnet access.

Network Discovery PBQ — Full Walkthrough

🎯 PBQ Prep — Network Discovery Simulation (Most Time-Consuming PBQ)

What it looks like: You are given a terminal connected to a switch. You have 4 available commands. You must find: the MAC address of a target device, its IP address, which VLAN it's on, and which port it connects to — possibly across multiple switches.

The 4 commands you get:

show mac address-table
show arp
show vlan
show ip interface brief
show power inline

Step-by-step process:

  1. Run show ip interface brief — confirms which interfaces are up/down and which IPs belong to this switch (SVIs)
  2. Run show vlan — shows which ports are in which VLANs (access ports only; trunk ports are not listed here)
  3. Run show mac address-table — maps MAC addresses to ports. If target MAC appears on a trunk port, the device is on a downstream switch
  4. Run show arp — maps IP addresses to MAC addresses (only populated if this is a Layer 3 switch or router)
  5. Run show power inline — displays PoE status per port: power class detected, watts allocated, and total switch power budget consumed vs. available. Use when a PoE device (AP, IP phone, camera) fails to power on despite being physically connected.

Sample output cross-reference scenario:

Switch1# show mac address-table
Vlan  Mac Address        Type    Ports
----  -----------------  ------  -----
10    0050.7966.6800     DYNAMIC Gi0/1    ← target device MAC on port Gi0/1
10    0050.7966.6801     DYNAMIC Gi0/2
20    0050.7966.6802     DYNAMIC Gi0/3

Switch1# show vlan
VLAN  Name      Status    Ports
----  --------  --------  ------
10    CORP      active    Gi0/1, Gi0/2
20    GUEST     active    Gi0/3

Switch1# show arp
Protocol  Address      Age  Hardware Addr    Interface
Internet  10.10.10.50  12   0050.7966.6800   Vlan10   ← MAC maps to IP 10.10.10.50

Conclusion: Target device MAC 0050.7966.6800 is on port Gi0/1, VLAN 10, IP address 10.10.10.50.

Multi-switch: If the MAC appears on a trunk port (e.g., Gi0/0), run the same commands on the downstream switch connected to that trunk port — the device is one hop further.

Time management: Candidates report spending 8–10 minutes on this PBQ unprepared. Practice in Packet Tracer until running these 4 commands and cross-referencing output takes under 3 minutes.

Exam strategy: Flag it, skip to MCQs, return with remaining time.

⚠ Exam Traps
  • show vlan only shows access ports — trunk ports don't appear in VLAN output
  • tracert * * * means ICMP is blocked at that hop, not necessarily that the hop is down
  • netstat -r shows routing table on a host (same as route print on Windows)
  • APIPA (169.254.x.x) = DHCP failure — not a bad IP address, a diagnostic signal
  • pathping is Windows only; combines ping + traceroute; shows per-hop loss statistics
  • show arp on a switch is only populated if the switch has SVIs (Layer 3 switch) or is a router
  • show power inline — use when a PoE device won't power up; shows per-port power class and switch budget consumed vs. available
  • iperf3 requires a server endpoint (iperf3 -s) and a client (iperf3 -c [ip]); reports actual achievable throughput, not just link capacity
✓ Quick Recall
  • 5 key discovery commands: show mac address-table, show arp, show vlan, show ip interface brief, show power inline
  • MAC→Port: show mac address-table
  • IP→MAC: show arp
  • Port→VLAN: show vlan
  • PoE device won't power on: show power inline
  • APIPA 169.254.x.x = DHCP server unreachable
  • DNS name fails but IP works → DNS issue, not routing
  • ipconfig /flushdns clears DNS resolver cache
  • Routing loop → traceroute shows packets cycling between same hops
  • iperf3 = active throughput measurement between two endpoints
