Objective 4.2

Network Attack Types

Layer 2 Attacks

AttackMethodImpactMitigation
ARP Spoofing / Poisoning Attacker sends fake ARP replies, associating their MAC with a legitimate IP (e.g., default gateway). Poisons ARP cache of victims. On-path (MITM) attack — attacker intercepts all traffic meant for gateway. Can eavesdrop, modify, or drop packets. Dynamic ARP Inspection (DAI), static ARP entries, encrypted protocols (HTTPS, SSH)
MAC Flooding Attacker sends thousands of frames with random source MACs, overflowing the switch's MAC address table. Switch enters "fail-open" mode and floods all frames to all ports — effectively acts like a hub. Attacker can capture all traffic. Port Security (MAC address limits per port), DHCP snooping
VLAN Hopping (Switch Spoofing) Attacker's device acts as a switch and negotiates a trunk link (using DTP), gaining access to all VLANs. Attacker can send/receive traffic on any VLAN. Disable DTP on all access ports (switchport nonegotiate), disable unused ports, put access ports in manual mode
VLAN Hopping (Double Tagging) Attacker sends frame with two 802.1Q tags. Outer tag = native VLAN (stripped at first switch), inner tag = target VLAN (forwarded by second switch). One-way traffic to target VLAN — useful for DoS, difficult to intercept data back. Change native VLAN to unused VLAN (not VLAN 1), tag the native VLAN explicitly
STP Attack Attacker sends superior BPDUs to become root bridge — all traffic rerouted through attacker's device. On-path attack. Traffic disruption during STP convergence. BPDU Guard on access ports, Root Guard on non-core-facing ports

Network Layer Attacks

AttackMethodMitigation
DoS (Denial of Service) Single attacker sends massive traffic or exploits vulnerability to exhaust resources (bandwidth, CPU, connections). Rate limiting, firewall rules, upstream ISP filtering, traffic scrubbing
DDoS (Distributed DoS) Attack launched from thousands of compromised hosts (botnet) simultaneously. Much harder to block by source IP. Cloud DDoS mitigation (Cloudflare, Akamai), ISP black-holing, anycast routing
Reflection/Amplification Attacker sends small request with spoofed source IP (victim's IP) to servers (DNS, NTP, SSDP). Servers send large responses to victim. BCP38 (source IP validation), disable amplification services, rate limiting on DNS/NTP
DNS Poisoning / Spoofing Injects false DNS records into resolver cache. Clients resolve legitimate names to attacker's IP — fake website, credential theft. DNSSEC (signed DNS records), secure recursive resolvers, short TTL
On-Path (MITM) Attacker positions between two communicating parties (via ARP spoofing, rogue WAP, etc.) — reads and/or modifies traffic. Encryption (TLS/HTTPS), certificate validation, VPN, MFA, HTTPS Strict Transport Security (HSTS)
IP Spoofing Attacker sends packets with a forged source IP address. Used in amplification attacks and to evade detection. BCP38 egress filtering, uRPF (Unicast Reverse Path Forwarding)

Wireless Attacks

AttackMethodMitigation
Evil Twin Attacker stands up an AP impersonating a legitimate SSID. Higher signal strength causes clients to associate with the attacker's AP instead of the real one, putting the attacker on-path. WIDS (Wireless IDS), 802.1X authentication (not just PSK), user education
Deauthentication Attack Attacker sends spoofed deauth frames (management frames are unauthenticated in WPA2), disconnecting clients. Forces reconnect — can capture handshake for offline cracking. WPA3 (management frame protection - PMF/802.11w), WIDS
WPS Attack (Pixie Dust) WPS PIN brute force or Pixie Dust attack — exploits WPS protocol weakness to recover WPA2 passphrase in seconds. Disable WPS on all APs
Wardriving Driving around with a laptop/antenna to discover and map wireless networks. Used to find open or weak networks. Strong encryption (WPA3), minimal signal broadcast outside facility

Rogue Devices and Services

A rogue device or service is one operating on the network without authorization. The category matters on its own because the cause is very often not an attacker — an employee plugging in a personal access point for better coverage, or a lab virtual machine left with a DHCP server enabled, produces the same exposure as a deliberate attack.

Rogue TypeWhat It IsImpactMitigation
Rogue DHCP Server An unauthorized device answering DHCP Discover messages. Because clients accept the first offer to arrive, a rogue server that responds faster than the legitimate one wins the race. Clients receive a wrong default gateway or DNS server — which hands the rogue operator an on-path position — or simply lose connectivity. DHCP snooping: mark uplinks trusted, access ports untrusted; only trusted ports may send DHCP Offers.
Rogue AP An unauthorized access point attached to the corporate network — commonly a consumer AP added by a well-meaning employee, often with weak or no encryption. Creates an unmonitored entry point that bypasses the perimeter entirely. The wired network is extended into the car park. Wireless IDS/IPS scanning for unknown BSSIDs, 802.1X on wired ports, port security, periodic site surveys.
Rogue AP vs. Evil Twin — Know the Difference

These are related but not the same attack, and the exam separates them.

  • Rogue AP — an unauthorized AP physically attached to your network. Usually not malicious in origin; the danger is the unmanaged backdoor into the wired LAN. It does not need to impersonate anything.
  • Evil Twin — an attacker-operated AP that impersonates a legitimate SSID to lure clients. It is typically not connected to your network at all; it only needs to look like it is.

Shorthand: a rogue AP is a connection problem (something unauthorized joined the network), an evil twin is an impersonation problem (something is pretending to be the network). An evil twin run on hardware that is also plugged into the LAN is both at once.

Malware

Net+ tests recognition of malware types and their network impact, not malware analysis. Know what each one is in a sentence and what it looks like on the wire.

TypeWhat Distinguishes It
VirusAttaches to a host file or program and requires a user to execute it in order to spread.
WormSelf-replicating and self-propagating — spreads across the network with no user action, which is why worms drive traffic spikes.
TrojanDisguised as legitimate software; the user installs it willingly. Often the delivery vehicle for a backdoor.
RansomwareEncrypts data and demands payment. An availability attack — hence the CIA mapping to A.
SpywareCovertly collects user activity and data, then exfiltrates it to the operator.
RootkitHides at OS or firmware level to conceal its own presence and maintain privileged access. Hardest to detect from the host itself.
KeyloggerRecords keystrokes to capture credentials. Exists as both software and inline hardware.
Botnet ClientTurns the host into a remotely controlled node used for DDoS, spam, or crypto-mining.
The Net+ Angle — Network-Observable Indicators

You are far more likely to be asked how malware presents on the network than how it works internally. Watch for unusual outbound traffic to unfamiliar destinations, C2 beaconing (regular, low-volume connections on a fixed interval — the regularity is the tell), lateral movement as a host suddenly scans or authenticates to peers it never touched before, and traffic on unexpected ports. These are the same indicators of compromise covered in 5.3 Network Troubleshooting, approached there from the diagnostic side.

⚠ Exam Traps
  • DAI (Dynamic ARP Inspection) prevents ARP spoofing — requires DHCP snooping to be configured first.
  • Port Security limits MAC addresses per port — mitigates MAC flooding. Default action = shutdown port.
  • VLAN hopping via native VLAN (double-tagging) only works in ONE direction — attacker can send traffic to target VLAN but cannot receive responses directly.
  • Evil twin = fake AP with same SSID. Deauth attack = forces disconnect. These are different attacks but often combined.
  • DNSSEC = signs DNS records with cryptographic signatures. Prevents cache poisoning.
  • Rogue AP ≠ evil twin. Rogue AP = unauthorized AP attached to your network, usually by an employee, no impersonation required. Evil twin = attacker-operated AP impersonating your SSID, usually not attached to your network at all.
  • Rogue DHCP wins because clients accept the first offer received — it does not need to defeat the real server, only to beat it.
  • Worm spreads by itself; a virus needs a user to run the infected file. If a scenario has no user interaction, it is a worm.
  • Ransomware attacks availability, not confidentiality — the data is still there, just inaccessible.
Quick Recall — 4.2

  • DNS poisoning → DNSSEC | Evil twin → 802.1X + WIDS | WPS → disable WPS
  • DoS = single source | DDoS = botnet (distributed) | Amplification = spoofed source + large responses
  • On-path (MITM) = attacker between two parties | ARP spoofing is a common on-path technique
  • Rogue AP = unauthorized AP on your network | Evil twin = attacker AP impersonating your SSID
  • Rogue DHCP → DHCP snooping (trusted vs. untrusted ports) | troubleshooting walkthrough in 5.3
  • Virus needs a user | Worm self-propagates | Trojan is disguised | Ransomware = availability attack
  • Rootkit hides itself | Keylogger captures credentials | Botnet client = remote-controlled host
  • Malware on the wire: odd outbound traffic, regular C2 beaconing, lateral movement, unexpected ports
  • Dumpster diving → shredding and secure disposal
