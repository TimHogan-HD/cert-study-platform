Objective 4.3

Network Hardening & Defense

Defense-in-Depth

Multiple overlapping security layers — if one fails, others prevent breach. No single control is sufficient.

  • Physical security → Network perimeter → Host-based → Application → Data → Monitoring

Security Zones — Trusted vs. Untrusted

Underneath any specific perimeter design sits a simple model: every firewall interface belongs to a zone, each zone carries a trust level, and rules are written between zones rather than between individual hosts.

ZoneTrust LevelWhat Lives ThereDefault Posture
UntrustedNoneThe internet, and any network outside your administrative controlDeny inbound by default; assume every host is hostile
Screened Subnet (DMZ)PartialPublic-facing servers that must be reachable from outside — web, mail, external DNSReachable from untrusted on specific ports; tightly restricted toward trusted
TrustedFull (traditionally)The internal corporate LAN — workstations, file servers, internal applicationsNever reachable directly from untrusted

The controlling principle is that traffic flows from higher trust to lower trust more freely than the reverse. A trusted workstation may open a session to the internet; the internet may not open a session to that workstation. The screened subnet exists precisely because some servers must be reachable from the untrusted side — putting them in a middle zone means that compromising a public web server does not hand the attacker the internal LAN.

Zero Trust Revises "Trusted"

This model assigns trust by location — being on the internal LAN implies trust. Zero trust (4.1 Security Concepts) rejects that assumption outright and re-verifies every request regardless of origin. Know the classic model, because zone terminology and firewall rule design are still built on it, but recognise that "internal, therefore trusted" is exactly what modern designs are moving away from.

DMZ Architecture

The DMZ (Demilitarized Zone) is a network segment between the internet and the internal network. Public-facing servers (web, email, DNS) sit in the DMZ — isolated from internal systems.

  • Traffic from internet can reach DMZ (with firewall rules).
  • Traffic from internet to internal network = blocked.
  • DMZ servers can connect to internal resources with strict rules (only specific ports/IPs).
  • Often implemented with two firewalls or a three-legged firewall (three interfaces).
Screened Subnet = DMZ (N10-009 Terminology)

CompTIA N10-009 uses the term "screened subnet" as the official synonym for DMZ. Both terms describe the same architecture: a network segment isolated between two firewall boundaries (or a three-legged firewall) where public-facing servers reside. If the exam uses "screened subnet," it means DMZ. The terms are interchangeable — know both.

Exam trap: UTM = all-in-one for SMB; NGFW = enterprise-grade deep packet inspection. Both operate at L7, but NGFW is more capable and scales better for enterprise.

Device Hardening

Hardening reduces the attack surface — the set of things an attacker can reach and attempt to use. Every live port and every listening service is one more thing that must be defended.

TechniqueWhat to DoWhy It Matters
Disable Unused Ports and Services Administratively shut down switch ports with nothing attached (shutdown), and turn off services a device does not need — Telnet, HTTP management, unused routing protocols, discovery protocols on edge-facing interfaces. An enabled port in an unlocked meeting room is network access for anyone with a patch cable. A listening service is a remotely reachable target whether or not it is patched.
Change Default Passwords Replace vendor default credentials on every device before it goes into service — switches, routers, APs, cameras, printers, IoT. Defaults are published in vendor documentation and collected into public lists. This is among the most reliably successful real-world compromise vectors, and it requires no exploit at all.

The two are halves of the same idea: disabling unused ports and services closes the paths you are not using, and changing default passwords closes the one that ships open. Note that disabling an unused port is stronger than relying on port security alone — port security governs who may use an enabled port, whereas hardening removes the port from play entirely.

Switch Security Features

FeaturePurposeWhat It Prevents
Port Security Limits number of MAC addresses allowed per port. Can sticky-learn or statically define allowed MACs. MAC flooding, unauthorized devices connecting to switch ports
DHCP Snooping Marks ports as trusted (uplinks) or untrusted (access). Only trusted ports can send DHCP offers/ACKs. Also builds binding table for DAI. Rogue DHCP servers, DHCP starvation attacks
DAI (Dynamic ARP Inspection) Validates ARP packets against DHCP snooping binding table. Drops ARP packets that don't match. ARP spoofing/poisoning (requires DHCP snooping first)
IP Source Guard Filters IP packets based on DHCP snooping binding table — only allows traffic from IPs/MACs that were legitimately assigned. IP spoofing at the access layer
802.1X NAC Requires authentication before granting network access at the port level. Port blocked until credentials verified by RADIUS. Unauthorized device access to the network
MAC Filtering Permits or denies devices by hardware address against an allowlist. Configured on switch ports, and very commonly on wireless APs. Casual unauthorized devices only — see the caveat below
⚠ MAC Filtering Is Not Access Control

A MAC address is neither secret nor verified. It travels in cleartext in the header of every single frame, so an attacker need only observe the wire or the air briefly to harvest a permitted address, then set their own interface to it with one command. Filtering also scales badly — every new or replaced device means a manual list edit.

MAC filtering raises the effort marginally and is not a substitute for 802.1X, which authenticates the device or user cryptographically before the port forwards any traffic at all. When a scenario asks for genuine network access control, the answer is 802.1X; MAC filtering is the distractor.

ACLs (Access Control Lists)

TypeMatch CriteriaNumber Range (Cisco)
Standard ACL Source IP address only 1–99, 1300–1999
Extended ACL Source + destination IP, protocol, port number 100–199, 2000–2699

ACL placement: Standard ACLs = place close to destination. Extended ACLs = place close to source (filter early, reduce unnecessary traffic).

URL Filtering vs. Content Filtering

ACLs filter on addresses and ports. These two act higher up the stack, and what separates them is what they examine.

PropertyURL FilteringContent Filtering
Acts OnThe destination — the web address itself, or the category it belongs toThe payload — what the traffic is actually carrying
Question It AnswersWhere is this going?What is being carried?
Typical DecisionBlock a category such as gambling or social media, or a specific named site, by reputation or classificationBlock executables, scripts, or attachments by file type; strip malicious content; catch data matching a sensitive pattern
Where It RunsNGFW, UTM, secure web gateway, proxyNGFW, UTM, email security gateway, DLP

They are complementary rather than alternatives. URL filtering will not stop a malicious executable downloaded from an allowed site, and content filtering will not stop a user reaching a site that is simply against policy. Both need TLS inspection to be useful against HTTPS traffic, since neither can act on what it cannot decrypt.

Key Management

Encryption is only ever as strong as the handling of its keys. An attacker who obtains a key has no need to break the algorithm — AES-256 with a leaked key provides exactly no confidentiality. Key management is the lifecycle that prevents that.

StageWhat It Involves
GenerationCreate the key at sufficient length from a cryptographically secure random source. Predictable generation is a break regardless of key size.
DistributionDeliver the key to the parties that need it without exposing it in transit — asymmetric key exchange, or an out-of-band channel.
StorageProtect the key at rest in an HSM, TPM, or dedicated key vault — never a config file or a source-code repository.
RotationReplace keys on a schedule. Limits how much data any single compromised key exposes, and shortens how long a stolen key stays useful.
RevocationInvalidate a key ahead of its natural expiry when it is compromised or the holder's access ends. CRL and OCSP do this for certificates.
DestructionSecurely destroy retired keys and every copy, so that recovered media cannot be used to decrypt archived data.
Cross-Reference — Objective 4.1

The PKI components implementing several of these stages — certificate authorities, CRL, and OCSP — are covered in 4.1 Security Concepts. PKI is the most visible key-management system on a network: issuance is generation and distribution, expiry and reissue are rotation, and CRL/OCSP is revocation.

⚠ Exam Traps
  • IDS = out-of-band (SPAN port), alerts only. IPS = inline, can block. This is the most important distinction.
  • DHCP snooping must be configured BEFORE DAI — DAI uses the DHCP snooping binding table.
  • Standard ACL = source IP only. Extended ACL = src + dst + port. Place standard ACLs near destination.
  • Vulnerability scanning ≠ penetration testing. Scanning finds potential vulnerabilities. Pen testing exploits them.
  • MAC filtering is trivially spoofable — MACs are cleartext in every frame header. It is never the right answer when a question asks for real network access control; that is 802.1X.
  • URL filtering acts on the destination; content filtering acts on the payload. "Where is it going?" vs. "What is it carrying?" Neither works on HTTPS without TLS inspection.
  • Disabling an unused port beats relying on port security for it — port security controls who may use an enabled port; disabling removes it entirely.
  • Key rotation limits exposure; key revocation handles compromise before expiry. A strong algorithm with a leaked key protects nothing.
  • Zones are about trust direction: higher trust may initiate toward lower trust, not the reverse. The screened subnet is the controlled middle, not a third "safe" network.
Quick Recall — 4.3
  • Device hardening: disable unused ports and services | change default passwords before deployment
  • NAC: 802.1X = real authentication | port security = MAC limits per port | MAC filtering = allowlist, spoofable
  • Key management: generation → distribution → storage → rotation → revocation → destruction
  • Security rules: ACLs = addresses/ports | URL filtering = destination | content filtering = payload
  • Zones: untrusted (internet) → screened subnet/DMZ (public servers) → trusted (internal LAN)
  • IDS = passive, SPAN port, alert only | IPS = inline, blocks traffic
  • NGFW = DPI + IPS + app awareness + SSL inspection
  • DHCP snooping = rogue DHCP prevention | DAI = ARP protection (needs snooping first)
  • Standard ACL = source IP only | Extended ACL = src+dst+port
