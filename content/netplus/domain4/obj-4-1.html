Network Security Concepts

CIA Triad

CIA Triad
PrincipleDefinitionThreat ExampleControl Example
Confidentiality Only authorized parties can access data Eavesdropping, data theft, unencrypted transmission Encryption (TLS, AES), access controls, VPN
Integrity Data has not been altered or tampered with Man-in-the-middle modification, data corruption Hashing (SHA-256), digital signatures, checksums

KEY DISTINCTION
Confidentiality = only authorized parties can read the data (encryption, ACLs). Integrity = data has not been altered (hashes, digital signatures). Availability = authorized users can access the system when needed (redundancy, DDoS protection). On the exam, match the failure to the leg: data leak → C, tampering → I, outage → A.

MFA (Multi-Factor Authentication)
MFA requires two or more different factor types. A password + PIN is NOT MFA — both are "something you know." A password + authenticator app code = MFA (know + have).

Encryption Types

TypeKeysSpeedUse CaseExamples
Symmetric Same key to encrypt and decrypt Fast Bulk data encryption (VPN tunnels, disk encryption) AES, DES, 3DES, ChaCha20
Asymmetric Public key to encrypt; private key to decrypt Slow (computationally expensive) Key exchange, digital signatures, TLS handshake RSA, ECC, DH (Diffie-Hellman), DSA
Hybrid Asymmetric to exchange key; symmetric for data Best of both TLS (HTTPS), SSH — real-world encryption TLS 1.3 (ECDH + AES)

Encryption in Transit vs. at Rest

StateWhat It ProtectsHow It Is DoneThreat It Answers
Data in Transit Data moving across a network — client to server, site to site, or host to cloud TLS/HTTPS, IPsec, SSH, WPA3, site-to-site VPN Eavesdropping and on-path modification while packets are on the wire
Data at Rest Data stored on a disk, array, backup tape, or database Full-disk encryption (BitLocker, LUKS), self-encrypting drives, database and backup encryption (AES) Theft or loss of the physical media, and unauthorized access to stored files
The Two Are Not Substitutes

Protecting one state says nothing about the other. A laptop with full-disk encryption still leaks credentials over an unencrypted HTTP session, and a TLS-protected web application still exposes its database if the drive is stolen. When a question describes stolen backup tapes or a lost laptop, the control is encryption at rest; when it describes packet capture or a hostile Wi-Fi network, it is encryption in transit.

PKI — Public Key Infrastructure

  • CA (Certificate Authority): Trusted entity that issues and signs digital certificates. (e.g., DigiCert, Let's Encrypt, internal enterprise CA).
  • Digital Certificate: Contains public key + identity information + CA signature. Proves "this public key belongs to this entity."
  • CRL (Certificate Revocation List): Published list of revoked certificates. Browser checks before trusting a cert.
  • OCSP (Online Certificate Status Protocol): Real-time cert validation — faster than downloading full CRL.
  • Root CA: The top of the trust hierarchy. Self-signed. Root CAs are embedded in OS/browser trust stores.
  • Intermediate CA: Signed by root CA; issues end-entity certificates. Allows root CA to stay offline.

Self-Signed vs. CA-Issued Certificates

PropertySelf-SignedCA-Issued
Signed ByIts own private key — subject and issuer are the same entityA Certificate Authority whose root is already trusted by the client
TrustNone by default — the client has no reason to trust the issuerChains up to a root in the OS or browser trust store
Client BehaviourCertificate warning until manually trusted or importedConnects silently
RevocationNo CRL or OCSP — nothing to revoke againstRevocable via CRL or OCSP
Cost / EffortFree, issued instantly with one commandValidation process; free (Let's Encrypt) through paid (EV certificates)
Appropriate UseLab and internal test systems; device management interfaces on an isolated networkAnything public-facing, and anything a user or partner must trust

A self-signed certificate provides the same encryption as a CA-issued one — the cipher suite and key length have nothing to do with who signed it. What it does not provide is identity assurance: nothing stops an attacker generating a self-signed certificate carrying your domain name. That is the entire reason for the browser warning, and why clicking through it on a public site defeats the point of TLS. Root CA certificates are also self-signed; the difference is that they are distributed in advance through the OS or browser trust store, so their trust is established out-of-band rather than by the certificate itself.

Zero Trust Security Model

  • "Never trust, always verify" — no implicit trust based on network location.
  • Requires authentication and authorization for every access request, regardless of whether the user is on-premises or remote.
  • Least privilege: users and devices get minimum permissions needed.
  • Microsegmentation: divide network into small segments with strict access controls between them.

AAA — Authentication, Authorization, Accounting

AAA is the model that every access-control system implements. The three A's answer three different questions, in order:

StageQuestion It AnswersIn Practice
AuthenticationWho are you?Verify the claimed identity — password, certificate, biometric, token. Proves the claim and grants nothing.
AuthorizationWhat may you do?Apply permissions to the now-known identity — RBAC role, VLAN assignment, privilege level, ACL.
AccountingWhat did you do?Log the session — commands entered, bytes transferred, connect and disconnect times. Feeds audit and billing.

Authentication without authorization gets you through the door with no permissions; authorization without authentication hands permissions to an unverified party. Accounting is the leg most often forgotten, and it is the one a question is asking about when it describes needing a record of who did what, and when.

Cross-Reference — Objective 3.5

The two AAA protocols, RADIUS and TACACS+, are compared in full in 3.5 Remote Access & Security alongside 802.1X. The consequence of the model to carry into that table: TACACS+ separates all three functions, so it can authorize an individual command on a router and log that command by itself, while RADIUS combines authentication and authorization into a single accept/reject exchange and keeps only accounting separate. That separation is why TACACS+ is the answer for device administration and RADIUS is the answer for network access.

⚠ IAM Exam Traps
  • SAML is the protocol; SSO is the outcome — SAML enables SSO, they are not synonyms.
  • Geofencing ≠ physical fence — it's a virtual geographic boundary enforced by policy.
  • RBAC ≠ ABAC: RBAC = role-based (job title); ABAC = attribute-based (department + time-of-day + clearance level).
  • LDAP port 389 = unencrypted; LDAPS port 636 = encrypted over TLS.

Security Terminology — Know the Distinctions

TermDefinitionExample
ThreatA potential cause of harm — an actor or event that could exploit a vulnerabilityA hacker attempting SQL injection; a ransomware gang
VulnerabilityA weakness in a system, configuration, or process that can be exploitedUnpatched OS, default password, open port
ExploitThe tool, technique, or code that takes advantage of a vulnerabilityMetasploit module, phishing email, buffer overflow code
RiskThe probability that a threat will successfully exploit a vulnerability × the impactRisk = Threat × Vulnerability × Impact
Risk Clarification

A vulnerability without a threat = no risk (no one to exploit it). A threat without a vulnerability = no risk (nothing to attack). Patching removes the vulnerability, not the threat — the attacker still exists, just can't exploit that vector anymore.

Deception Technologies

Deception technologies are decoys deployed in order to be attacked. They hold no production data and have no legitimate users, and that is exactly what makes them useful: any interaction with one is suspicious by definition, so they generate almost no false positives.

TechnologyWhat It IsWhat It Gives You
Honeypot A single decoy system left deliberately exposed and made to look like an attractive target — often running intentionally weak or outdated services. Early warning that an attacker is already inside, plus a record of the techniques and tooling being used against you.
Honeynet An entire decoy network of honeypots — servers, workstations, and plausible traffic between them — simulating a complete environment. The same intelligence at greater depth. An attacker who moves laterally through a honeynet reveals far more of the attack chain than one probing a single host.

Both are detective controls, not preventive ones. A honeypot blocks nothing — it watches, records, and buys time.

⚠ OT/ICS CIA Priority — High-Frequency Exam Scenario

OT/ICS/SCADA systems prioritize AVAILABILITY over Confidentiality and Integrity — the opposite of standard IT. A power grid or water treatment plant being inaccessible (unavailable) is catastrophic and potentially life-threatening; a brief loss of confidentiality is a secondary concern. When a CompTIA question involves industrial control systems and asks which CIA principle is most important, the answer is Availability.

⚠ Exam Traps
  • Confidentiality → encryption | Integrity → hashing | Availability → redundancy. Match the right control to the right principle.
  • MFA requires different factor TYPES. Two passwords ≠ MFA.
  • Asymmetric encryption is slow — not used for bulk data. TLS uses asymmetric for handshake then switches to symmetric.
  • MD5 is broken for security purposes. SHA-256 is the current standard.
  • Honeypots are decoys, NOT production systems. They intentionally carry fake vulnerabilities and hold no real data. A honeypot detects — it never blocks.
  • TACACS+ separates all three AAA functions; RADIUS does not — RADIUS combines authentication and authorization. This is why TACACS+ can authorize individual commands.
  • Self-signed and CA-issued certificates give the same encryption strength. Only the CA-issued one gives identity assurance.
  • Encryption at rest and encryption in transit are separate controls — solving one does not solve the other.
Quick Recall — 4.1
  • CIA: Confidentiality (encryption) | Integrity (hashing/signing) | Availability (redundancy)
  • Auth factors: Know (password) | Have (token) | Are (biometric) | Where (location)
  • Symmetric = same key, fast (AES) | Asymmetric = key pair, slow (RSA)
  • SHA-256 = current hash standard | MD5/SHA-1 = deprecated/broken
  • Zero trust = never trust, always verify; least privilege everywhere
  • AAA: Authentication (who are you) | Authorization (what may you do) | Accounting (what did you do)
  • TACACS+ separates all three A's | RADIUS combines authentication + authorization → see 3.5
  • In transit = TLS/IPsec/VPN | At rest = full-disk, database, and backup encryption
  • Self-signed = same crypto, no identity assurance, no revocation | CA-issued = chains to a trusted root
  • Deception: honeypot = one decoy host | honeynet = a whole decoy network. Both detective, never preventive
  • SSO = outcome; SAML = protocol that enables it | Geofencing = location-based access control
  • Threat × Vulnerability = Risk | Patching removes vulnerability, not threat
  • PCI DSS = CDE segmentation required | GDPR = data locality, 72-hr breach notice
  • OT/ICS/SCADA = Availability is #1 priority (inverse of standard IT CIA order)
  • Mantrap/vestibule = prevents tailgating (two doors, one at a time)
