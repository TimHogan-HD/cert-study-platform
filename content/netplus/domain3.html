Performance Metrics to Monitor

MetricDefinitionIssue When…
BandwidthMaximum data rate of a link (bps)Utilization consistently >80% — risk of congestion
ThroughputActual data transfer rate achievedFar below bandwidth — indicates loss, errors, or protocol overhead
LatencyTime for data to travel from source to destination (ms)>150ms one-way — VoIP quality degrades; >100ms round-trip may affect interactive apps
JitterVariation in packet delay (ms)>30ms — VoIP and streaming audio/video suffer
Packet LossPercentage of packets that don't arrive>1% — noticeable performance issues; >5% VoIP is unusable
Error RateRatio of errored frames to total framesAny significant errors — indicates physical layer issues
⚠ Exam Traps
  • Bandwidth ≠ throughput. Bandwidth is the link capacity; throughput is what you actually get.
  • A baseline is taken before a problem occurs — it represents "normal." You compare current metrics against it.
  • Change management includes a rollback plan — what to do if the change causes issues.
Quick Recall — 3.1
  • Logical diagram = IP/VLAN/routing info | Physical diagram = locations/racks/cables
  • Baseline = normal performance snapshot for comparison
  • Jitter = packet delay variation — bad for VoIP | Latency = total one-way delay
  • Change management: request → approval → implementation → verification → documentation

SNMP Trap vs Poll Direction
Poll (Get): NMS manager initiates — sends request to agent on port 161. Agent responds with data.
Trap: Agent initiates — sends unsolicited alert to NMS manager on port 162. Triggered by an event (interface down, high CPU, etc.)

Syslog

Syslog sends system log messages to a central syslog server (port 514 UDP). All devices can log to one central repository for correlation and compliance.

⚠ Exam Traps
  • SNMP trap: agent sends TO manager on port 162. Manager polls agent on 161. Direction matters!
  • Syslog severity 0 = Emergency (most severe). 7 = Debug (least severe). Lower number = worse problem.
  • SNMPv3 is the only version with authentication AND encryption. SNMPv1/v2c = community strings (cleartext).
  • NMS ≠ SIEM. NMS focuses on device performance. SIEM focuses on security events and correlation.
Quick Recall — 3.2
  • SNMP: Manager polls agent on 161 UDP | Agent sends trap to manager on 162 UDP
  • SNMPv3 = authentication + encryption (SHA/AES). v1/v2c = community strings only.
  • Syslog: 0=Emergency (worst) → 7=Debug (least severe). Port 514 UDP.
  • NetFlow = active flow export | sFlow = passive sampling | IPFIX = open standard of NetFlow
  • SIEM = security event correlation | NMS = network performance management

DHCP, DNS & NTP

DHCP — DORA Process

DHCP automates IP address assignment. The DORA process is the four-step handshake:

D
Discover (Client → Broadcast)
Client has no IP. Sends broadcast (255.255.255.255) from 0.0.0.0. Asks "Is there a DHCP server?" Src port: 68, Dst port: 67.
O
Offer (Server → Broadcast/Unicast)
DHCP server responds with an IP address offer — IP, mask, gateway, DNS, lease time. Can be broadcast (client has no IP yet) or unicast.
R
Request (Client → Broadcast)
Client accepts the offer. Sends broadcast request so all servers know which offer was accepted (multiple servers may have offered).
A
Acknowledge (Server → Client)
Server confirms the lease. Client can now use the assigned IP address. Lease timer starts.

DHCP Relay (IP Helper)

DHCP uses broadcasts — routers don't forward broadcasts between subnets. A DHCP Relay Agent (configured with ip helper-address on the router) forwards DHCP broadcasts from clients to the DHCP server as unicast, enabling one DHCP server to serve multiple subnets.

DNS Hierarchy

  1. Root DNS Servers: 13 logical root server sets (a.root-servers.net through m.root-servers.net). Know where top-level domains (TLDs) are.
  2. TLD Name Servers: Manage .com, .org, .net, country codes (.uk, .de).
  3. Authoritative Name Servers: Hold actual DNS records for a domain. Final authority.
  4. Recursive Resolver: Your ISP or internal DNS server. Queries on behalf of clients, caches results (TTL-based).

NTP (Network Time Protocol)

StratumSourceExamples
Stratum 0Reference clock (not on network)Atomic clocks, GPS receivers, CDMA
Stratum 1Directly connected to Stratum 0time.nist.gov — authoritative NTP servers
Stratum 2Synced from Stratum 1pool.ntp.org servers, enterprise NTP servers
Stratum 3+Cascaded from higher stratumLocal network NTP servers, endpoint clients
Stratum 16UnsynchronizedDevice has lost sync — clock is unreliable
NTP and Kerberos
Kerberos authentication (used in Active Directory) requires all devices to be within 5 minutes of each other in clock time. If NTP fails and clocks drift more than 5 minutes, Kerberos tickets will be rejected and users can't authenticate. NTP is security-critical.
⚠ Exam Traps
  • DHCP uses broadcasts — routers don't forward broadcasts. You need a DHCP relay (ip helper-address) for multi-subnet DHCP.
  • PTR record = reverse DNS. A record = forward (name → IP). These are commonly confused.
  • CNAME cannot point to an IP address directly — it points to another hostname (which then resolves via an A record).
  • MX records have priority values — lower number = higher priority. Multiple MX records for redundancy.
  • DNS uses UDP for queries ≤512 bytes and TCP for zone transfers or larger responses.
  • NTP stratum 0 = hardware clock (not on network). Stratum 1 = first server on the network.
Quick Recall — 3.3
  • DHCP DORA: Discover (broadcast) → Offer → Request (broadcast) → Acknowledge
  • DHCP options: 3=gateway, 6=DNS, 15=domain, 51=lease time, 66=TFTP, 67=bootfile
  • ip helper-address = DHCP relay for cross-subnet DHCP
  • A=IPv4 | AAAA=IPv6 | MX=mail | PTR=reverse | CNAME=alias | TXT=SPF/DKIM
  • NTP: Stratum 0=atomic clock → 1=primary server → 2=secondary → 16=unsynchronized

Remote Access & AAA

VPN Types

TypeDescriptionUse Case
Site-to-Site VPN Permanent tunnel between two network sites (typically router-to-router). All traffic between sites traverses encrypted tunnel. Branch office to HQ connectivity; replaces dedicated WAN circuits.
Client-to-Site (Remote Access VPN) Individual user connects VPN client to corporate network over internet. Full tunnel = all traffic goes through VPN. Split tunnel = only corporate traffic goes through VPN. Remote workers, WFH employees.
SSL/TLS VPN Uses HTTPS (port 443) — traverses firewalls easily. Browser-based or thin client. (Also called SSTP, OpenVPN). Clientless access to web apps, easy deployment through NAT/firewalls.
IPsec VPN IP Security — encrypts/authenticates at Layer 3. Uses IKE for key exchange. Site-to-site and client-to-site. Most common enterprise VPN protocol.

IPsec Components

ComponentFunction
AH (Authentication Header)Provides authentication and integrity only. NO encryption. Protocol number 51. Not widely used alone.
ESP (Encapsulating Security Payload)Provides authentication, integrity, AND encryption. Protocol number 50. Most common IPsec component.
IKE (Internet Key Exchange)Negotiates security associations (SAs) and establishes shared keys. IKEv1 (older) and IKEv2 (current, more efficient). Uses UDP port 500 (phase 1) and UDP 4500 (NAT traversal).
Tunnel ModeEntire IP packet is encrypted and encapsulated in new IP packet. Used for site-to-site VPNs.
Transport ModeOnly the payload is encrypted; original IP header preserved. Used for host-to-host encryption (e.g., L2TP over IPsec).

⚠ Exam Traps
  • RADIUS = UDP | TACACS+ = TCP. This is the #1 most-tested RADIUS/TACACS+ fact.
  • TACACS+ encrypts the entire packet. RADIUS encrypts only the password.
  • TACACS+ is for device (router/switch) management. RADIUS is for network access (Wi-Fi, VPN).
  • IPsec ESP provides encryption. IPsec AH does NOT encrypt — it only authenticates.
  • 802.1X supplicant = client. Authenticator = switch/WAP. Authentication server = RADIUS.
Quick Recall — 3.4
  • RADIUS: UDP 1812/1813, encrypts only password, combines Auth+Authz
  • TACACS+: TCP 49, full packet encryption, separates AAA functions
  • IPsec: AH=auth only | ESP=auth+encryption | IKE=key exchange
  • 802.1X: Supplicant (client) → Authenticator (switch/WAP) → Authentication Server (RADIUS)
  • Site-to-site VPN = router-to-router | Remote access VPN = client-to-site
Objective 3.5

Network Policies & Disaster Recovery

RPO vs RTO — Most Tested DR Terms

TermDefinitionSimple Question
RPO
(Recovery Point Objective)		 Maximum acceptable data loss, measured in time. How old can the restored data be? "How much data can we afford to lose?" → If RPO = 4 hours, backups must run every 4 hours.
RTO
(Recovery Time Objective)		 Maximum acceptable downtime. How quickly must systems be restored? "How long can we be down?" → If RTO = 1 hour, systems must be back up within 1 hour of failure.
MTTR
(Mean Time to Repair)		 Average time to restore a failed system/component. Lower MTTR = faster recovery capability.
MTBF
(Mean Time Between Failures)		 Average time between system failures. Higher MTBF = more reliable system. Used in hardware specs.

Backup Types

TypeWhat's Backed UpArchive Bit AfterRestore TimeStorage
Full All data, regardless of change Cleared Fastest (1 backup set) Most space
Incremental Only data changed since last backup (full or incremental) Cleared Slowest (need full + all incrementals) Least space
Differential All data changed since last full backup NOT cleared Medium (need full + latest differential) Grows over time until next full

Disaster Recovery Site Types

Site TypeDescriptionRTOCost
Hot Site Fully operational duplicate — live systems, real-time data replication. Just redirect traffic. Minutes to hours Very high
Warm Site Partially equipped — hardware present, data restored from backups. Some configuration needed. Hours to days Medium
Cold Site Just a space with power/connectivity — no hardware or data. Must provision everything. Days to weeks Lowest
Cloud DR Cloud-based failover — spin up cloud resources in another region on-demand. Minutes to hours (with automation) Pay-as-you-go

High Availability Concepts

  • Redundancy: Duplicate critical components — dual power supplies, redundant network links, multiple ISPs.
  • Failover: Automatic switch to backup system when primary fails (active-passive). Or both active simultaneously (active-active).
  • Load Balancing: Distributes traffic across multiple servers — improves performance AND provides failover if one server dies.
  • NIC Teaming / Bonding: Multiple NICs combined for bandwidth and redundancy. If one NIC fails, traffic continues on others.
  • UPS: Uninterruptible Power Supply — provides battery backup to bridge power outages and allow graceful shutdown.
  • Generator: Long-term power backup for extended outages (hours to days).

⚠ Exam Traps
  • RPO = data loss tolerance. "We can't lose more than 2 hours of data" → RPO = 2 hours. Backup frequency must match.
  • RTO = downtime tolerance. "Systems must be back up within 4 hours" → RTO = 4 hours.
  • Differential grows larger each day (until next full). Incremental stays small (only daily changes).
  • Restore from incremental = full + EVERY incremental. Differential = full + LATEST differential only.
  • Hot site costs the most. Cold site costs the least. RTO inversely correlates with cost.
Quick Recall — 3.5
  • RPO = how much data can be lost (backup frequency) | RTO = how fast to recover (downtime tolerance)
  • Full = all data | Incremental = changes since last backup (fast backup) | Differential = changes since last full
  • Hot site = live systems, minutes to recover | Warm = hours | Cold = days
  • MTBF = reliability (time between failures) | MTTR = recovery speed
