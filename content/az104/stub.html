How VNet Peering Works — and Why It Is Non-Transitive
VNet Peering creates a direct, low-latency link between two VNets using Microsoft's backbone network (not the public internet). Traffic between peered VNets is encrypted and does not traverse the internet. Peering is non-transitive because each peering is an independent configuration object — Azure does not automatically chain them. If VNet-A peers with VNet-B, and VNet-B peers with VNet-C, the routing table in VNet-A only knows about VNet-B's address space. VNet-C is unknown to VNet-A. To enable A↔C communication, you must create a third peering explicitly between A and C. The alternative is to deploy a hub-spoke topology with Azure Firewall or a Network Virtual Appliance in the hub, which can route between spokes.
Exam trap
VNet Peering ≠ connecting to PaaS
"Connect Azure SQL to a VNet" = Service Endpoint or Private Endpoint. VNet Peering only connects VNet to VNet.
Exam trap
VNet Peering is non-transitive
A↔B and B↔C does NOT give A↔C. Each pair needs an explicit peering created.

Azure Data Lake Storage — What It Is and How It Relates to Blob

Azure Data Lake Storage Gen2 is not a separate, standalone service — it is Azure Blob Storage with the hierarchical namespace (HNS) feature enabled. When you create a storage account and turn on hierarchical namespace, you get all Blob Storage capabilities plus true directory semantics, POSIX permissions, and compatibility with big data frameworks like Apache Spark and Hadoop.

CapabilityStandard Blob StorageData Lake Gen2 (Blob + HNS)
Underlying serviceAzure BlobAzure Blob (same infrastructure, same storage account)
Directory structureFlat — "folders" are just naming prefixes in object keysTrue hierarchical filesystem — directories are real objects with atomic operations
Rename a directoryMust copy every object with a new prefix and delete originals — O(n), slow and expensive at scaleAtomic metadata update — O(1), milliseconds regardless of how many files are inside

When to choose standard BlobUse standard Blob when you need simple object storage without big data analytics — static website hosting, CDN origin files, backup archives, media files, application logs at small/medium scale. No need to pay for HNS namespace operation costs.
When to choose Data Lake Gen2Use Data Lake Gen2 when you have petabyte-scale datasets, need Spark/Databricks/Synapse integration, have data engineering pipelines that rename/move directories frequently, or need POSIX-level permissions for data governance.
The Analytics Pipeline: Where Data Lake Fits
A typical Azure analytics architecture: (1) Ingest — raw data lands in Data Lake Gen2 from databases, IoT devices, event streams, and file exports. This is the "bronze" raw layer. (2) Transform — Azure Databricks or Synapse Spark pools read raw data, clean and join it, and write curated "silver" and "gold" layers back to Data Lake. (3) Serve — clean aggregated data is loaded into Azure Synapse dedicated SQL pools or Azure SQL Database for reporting, or served directly from Data Lake via Synapse Serverless SQL. This is why Data Lake appears in "big data" and "analytics pipeline" questions — it is the central raw data repository, not a monitoring or logging tool.
Exam trap
Azure Data Lake = big data storage, not monitoring
Data Lake is frequently offered as a wrong answer for monitoring and logging questions because it stores large volumes of data. But it has no real-time alerting, no dashboards, and no KQL. To correlate events from multiple Azure resources → Log Analytics. To aggregate resource metrics and trigger alerts → Azure Monitor. Data Lake is for data scientists and analytics engineers, not operations teams.

Conditional Access — How It Actually Works
Conditional Access is a policy engine that runs at sign-in time. It evaluates signals — who is signing in (user identity, group membership), what they are signing into (which app), where they are (IP address, named location, country), how risky the sign-in is (Identity Protection risk score), and what device they are using (compliant, managed, or unmanaged). Based on these signals, it applies access controls: allow, block, require MFA, require compliant device, or require agreed terms of use. Conditional Access does NOT protect documents after access is granted — it only enforces access at the moment of authentication.

Monitoring Tools

Azure's monitoring stack is layered. Azure Monitor is the foundation that everything else sits on top of or feeds into. Understanding the relationships between services prevents confusing them on scenario questions.

How the Monitoring Services Relate to Each Other
Azure Monitor is the collection platform — it ingests metrics (numerical time-series data) and logs (structured event data) from all Azure resources automatically. Log Analytics workspaces are where those logs are stored and queried with KQL. Application Insights is a sub-resource that adds application-level instrumentation on top of Log Analytics — its data flows into a Log Analytics workspace. Azure Alerts are configured rules inside Monitor that watch metrics or log query results and fire when thresholds are crossed, triggering Action Groups. Azure Advisor is separate from Monitor — it analyzes resource configuration and billing data to make recommendations, but does not ingest real-time metrics. Defender for Cloud is also separate — it reads resource configurations against security policy benchmarks, not real-time operational data. Microsoft Sentinel ingests from Monitor, Defender for Cloud, and external sources to provide security analytics.

All Exam Traps — Grouped by Topic

⚡ Compute & VMs
Exam trap
Stopped VM ≠ no compute charges
Must be stopped (deallocated). "Stopped" from inside the OS still bills compute. Only deallocating from Azure portal/CLI stops the meter. Storage is always charged regardless.
Exam trap
ARM is the control plane, not a tool
Portal, CLI, and PowerShell are clients that send requests TO Azure Resource Manager. ARM is the layer behind all of them — not one of the tools.
🌐 Networking & Storage
Exam trap
VNet Peering is non-transitive
A↔B + B↔C ≠ A↔C. Each pair requires its own explicit peering. No peering automatically enables transitivity.
Exam trap
GRS ≠ read access to secondary
GRS and GZRS require a failover event before the secondary becomes readable/writable. Only RA-GRS and RA-GZRS allow reads from the secondary region without a failover.
Exam trap
Ingress is free, egress is charged
Inbound data to Azure = free. Outbound data (egress) is billed. Bandwidth cost is one-directional.
🔐 Identity & Governance
Exam trap
Owner role does NOT bypass locks
Resource locks override ALL RBAC roles including Owner. The lock must be explicitly removed before any changes can be made — even by an Owner.
Exam trap
Tags don't auto-inherit
Tags on a resource group do NOT propagate to resources inside it. To enforce inherited tagging, use Azure Policy with a Modify or DeployIfNotExists effect.
Exam trap
RBAC vs Azure Policy — different controls
RBAC = WHO can do WHAT (user/group permissions). Policy = WHAT can be deployed and HOW (resource compliance). These are frequently swapped on exam questions.
🏗️ Architecture & SLAs
Exam trap
Availability Sets vs Availability Zones
Sets = rack-level protection within one DC → 99.95%. Zones = full datacenter failure protection across physically separate DCs → 99.99%. "99.99% uptime" always = AZs, never Sets.
Exam trap
Region pairs are Microsoft-defined
You cannot choose or customize region pairs. Microsoft defines them, minimum 300 miles apart. Used for planned maintenance ordering and geo-redundant storage replication.
Exam trap
Free tier = no financially backed SLA
Any SLA guarantee requires a paid service tier. Free tier = no SLA. Cannot use free tier for anything requiring uptime guarantees.
☁️ Cloud Models & Monitoring
Exam trap
Hybrid ≠ multi-cloud
Hybrid = public cloud + private cloud (or on-prem). Multi-cloud = multiple public cloud providers (Azure + AWS + GCP). These are distinct architectures with different exam answers.
Exam trap
On-prem Hyper-V = Private Cloud, not Hybrid
Virtualized on-prem infrastructure that the org owns and operates = Private Cloud. Hybrid requires a live connection between on-prem and a public cloud. Shared Hyper-V in your own datacenter = Private.
Exam trap
Cosmos DB / Azure MySQL / App Service = PaaS, not SaaS
SaaS = end-user apps (Office 365, Dynamics 365). PaaS = developer platforms (App Service, Azure SQL, Cosmos DB, Azure MySQL, Event Grid). If a developer deploys code or data to it, it's PaaS.
Exam trap
Functions vs Logic Apps — both serverless, different style
Functions = code-first (write code). Logic Apps = designer/workflow-first (visual, no-code). Both are serverless. "Serverless" alone does not imply App Service — App Service is always-on PaaS.
Exam trap
RCA reports → Service Health, not Azure Monitor
Post-outage root cause analysis reports live in Azure Service Health. Not Azure Monitor. Not Log Analytics. Service Health is also where planned maintenance notifications appear.
Exam trap
Azure Data Lake ≠ monitoring
Azure Data Lake is big data storage for analytics pipelines. To correlate events from multiple Azure resources → Log Analytics. To alert on resource metrics → Azure Monitor. Never choose Data Lake for a monitoring or alerting question.
🔒 Identity & Security Services
Exam trap
Identity Protection (cloud) vs. Defender for Endpoint (on-prem AD)
Azure Identity Protection = detects risky sign-ins and compromised Entra ID (cloud) identities. Microsoft Defender for Endpoint = protects devices AND on-premises Active Directory identities. They are mirror opposites — match to the environment in the question.
Exam trap
Defender for Cloud = compliance; Advisor = optimization
Microsoft Defender for Cloud handles security posture and regulatory compliance baselines (HIPAA, PCI DSS). Azure Advisor gives cost, performance, reliability, and operational recommendations. "Verify regulatory compliance" → Defender for Cloud. "Reduce costs / improve performance" → Advisor.
Exam trap
Purview vs. Conditional Access for document protection
Microsoft Purview protects sensitive documents wherever they travel — outside the org, on personal devices, downloaded. Conditional Access controls access based on conditions (location, device) but doesn't travel with the document itself.
Exam trap
NSG is sufficient for a single VM; Firewall for multi-VNet
Adding an NSG inbound rule for ports 80/443 fully satisfies "expose a VM web app to the internet." Azure Firewall is the answer only when centralized inspection across multiple VNets is needed. Don't over-engineer single-VM questions.
Exam trap
Same-VNet subnets communicate by default
VMs in different subnets of the SAME VNet can talk by default. VMs in DIFFERENT VNets cannot — they need VNet Peering. NSGs can restrict intra-VNet traffic, but without an explicit deny rule, it flows freely.

Log Analytics vs. Azure Data Lake — Why They Get Confused
Both store large volumes of data. Log Analytics is an operational monitoring store — structured Azure telemetry, 30-day default retention, KQL queries, used by operations teams asking "what is happening right now?" Azure Data Lake is a data engineering platform — raw data in any format (CSV, Parquet, images), petabyte scale, used by data scientists running batch jobs and ML training pipelines. Exam trap Azure Data Lake ≠ monitoring

A question asking how to allow inbound HTTP/HTTPS to a single VM has a correct answer of "add an NSG inbound rule on port 80/443." Azure Firewall for this scenario is over-engineered and wrong. Firewall is for centralized, multi-VNet policy.

Monitor Alert → Azure Automation
Azure Monitor Alerts trigger Action Groups, which can invoke an Azure Automation runbook. When a question says "when CPU breaches a threshold, automatically scale down idle VMs" or "when a security alert fires, isolate the affected resource" — the answer is Azure Automation. Power Automate has no native Azure Monitor integration and is not designed for infrastructure remediation.
Exam trap Respond to Monitor alert → Azure Automation, not Power Automate
Power Automate is for business-process automation between SaaS applications. Azure Monitor alerts → Action Group → Automation runbook is the correct chain for infrastructure auto-remediation.
🛡️ Azure DDoS Protection

A DDoS attack overwhelms a service with traffic from thousands of compromised systems, making it unavailable to legitimate users. Azure defends at two levels.

Always-on, free, no configuration — automatic protection for all Azure customers
→ DDoS Basic (Infrastructure Protection)
Regulatory compliance, SLA-backed mitigation, attack analytics, DRR team access
→ DDoS Standard (Network Protection)
